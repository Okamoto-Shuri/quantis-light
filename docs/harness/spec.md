# Quantis Light 製品仕様書

## 元のプロンプト
> TypeScript・Next.js・shadcn/ui・Vercel・Supabase(ログイン必須)で、J-Quants API Standardプラン＋EDINET APIを使う日本株スクリーニングアプリを作る。
> 条件は4つで、閾値は画面で変更できる: ①直近4期の売上CAGR≥20% ②直近通期の営業利益率≥10% ③上場5年以内（株価データの初出日から推定） ④オーナー企業または社長が筆頭株主（EDINETの有報で大株主と役員を照合して自動判定）。
> データはVercel CronでSupabaseに毎日取り込み、画面は保存済みデータを検索する。J-Quantsの再配布禁止に合わせ、閲覧はログインした本人に限る。

## ユーザーと合意済みの補足
- 技術スタック（TypeScript / Next.js / shadcn/ui / Vercel / Supabase / Vercel Cron）はユーザー指定の制約として扱う。それ以外の実装詳細（DB スキーマ、API 設計、ライブラリ選定など）はジェネレーターが決める。
- 条件④はヒューリスティック判定なので誤判定がありうる。判定根拠（筆頭株主名、社長名、照合結果など）を画面で必ず確認できるようにする。
- 外部 API キー（J-Quants, EDINET）が無い環境でも検証できるようにする。キー未設定時は明示的なエラーとして表示する。スタブやダミーデータで動いているように見せる設計は禁止（詳細は「検証方針」を参照）。
- 条件①「直近4期の売上CAGR」は、ユーザーの決定により「直近5期の通期実績から算出する成長4年分の CAGR」と解釈する（定義は「用語と算出ルール」を参照）。
- 条件④のオーナー企業判定（オーナー系株主の合計持株比率 ≥20%、閾値は画面で変更可）は、ユーザーが承認済み。さらに、一覧と詳細の両方で「誰がどの程度の比率を持っているか」という保有状態の内訳を表示する。

## プロダクト概要
- **ビジョン**: 「若くて、急成長していて、儲かっていて、経営者が自分ごととして株を持っている」日本の上場企業を、毎朝自動で更新されるデータから数秒で絞り込めるようにする、個人投資家向けの自分専用スクリーナー。条件④のようなスクリーナーでは普通扱わない条件も、有価証券報告書から自動で判定し、判定根拠まで画面で確認できる。
- **対象ユーザー**: 成長株・小型株に投資する個人投資家。自分で J-Quants Standard プランを契約しており、自分だけが使う。
- **コア体験（最初の5分）**:
  1. ログインすると、最終取り込み日時と対象銘柄数がダッシュボードに表示される。
  2. スクリーニング画面を開くと、既定の4条件（売上CAGR ≥20%、営業利益率 ≥10%、上場5年以内、オーナー企業または社長が筆頭株主）での該当銘柄一覧がすぐ表示される。一覧の各行では、オーナー系株主の保有状態の内訳を簡潔に確認できる。
  3. スライダーや入力欄で閾値を変える（例: CAGR 20% → 15%）と、該当件数と一覧がすぐ更新される。
  4. 気になる銘柄をクリックすると、5期分の売上推移、営業利益率、株価データの初出日、大株主上位と役員の一覧、保有状態の内訳、条件④の判定根拠（「筆頭株主: 山田太郎 32.1% ＝ 代表取締役社長: 山田太郎」など）が確認できる。

## 技術的制約（ユーザー指定）
- 言語・フレームワーク: TypeScript、Next.js
- UI コンポーネント: shadcn/ui
- ホスティング・定期実行: Vercel、Vercel Cron
- 認証・データ保存: Supabase（全画面ログイン必須）
- データソース: J-Quants API（Standard プラン）、EDINET API
- 画面はすべて保存済みデータを検索する。ユーザー操作をきっかけに外部 API をリアルタイムで呼んで一覧を作ってはいけない（手動の取り込み再実行を除く）。

## コンプライアンス要件（J-Quants 再配布禁止への対応）
- 市場データ（銘柄、株価由来の情報、財務値、算出指標）は、ログイン済みで許可されたユーザーにしか表示・返却しない。未ログインのリクエストには、画面でもデータ取得用のエンドポイントでも、データを一切返さない。
- 誰でも見られる共有リンク、公開ページ、埋め込みウィジェット、データのエクスポート（CSV など）は作らない。
- 新規登録は自由にはできない。許可されたメールアドレスのユーザーだけがログインできる。
- データベースに保存したデータは、公開用のクライアントキーだけでは読み出せないようにする。
- フッターなどにデータ出典（J-Quants、EDINET）と「投資助言ではない」旨の注記を表示する。

## 検証方針（API キーが無い評価環境への対応）
- **ダミーデータの禁止**: アプリ本体にサンプル銘柄やダミーデータを同梱して、画面に表示してはいけない。データが無いときは「未取り込み」を示す空状態を表示する。
- **キー未設定時の振る舞い**: J-Quants または EDINET の認証情報が未設定のまま取り込みを実行した場合、取り込みは失敗として記録される。取り込み状況画面には、どのデータソースのキーが未設定なのかが日本語で明示される（例: 「J-Quants の API キーが設定されていません」）。無言で成功扱いにしたり、空データを成功として記録したりしてはいけない。
- **評価用のデータ投入**: 取り込み後の機能（スクリーニング、詳細表示、判定など）を検証するため、エバリュエーターは Supabase のデータベースに検証用レコードを直接投入してよい。ジェネレーターは、投入に必要な保存形式を契約書（contract.md）で説明する。アプリが取り込んだデータと同じ経路で読み出され、表示されること。
- **自動テスト用フィクスチャ**: 指標の算出、有報の解析、オーナー判定などのロジックは、テストコードの中で実データの形をしたフィクスチャ（EDINET 有報の該当部分など）を使って検証してよい。ただしフィクスチャが実行中のアプリの画面に出てはいけない。
- キーがある環境では、実際の API から取り込んだデータで同じ受け入れ基準を満たすこと。

## デザインの方向性
- 落ち着いた、情報密度の高い金融ツール。装飾より数値の読みやすさを優先する（数値は右揃えで桁をそろえ、パーセントや円の単位は一貫した書式にする）。
- ライト／ダークの両テーマに対応する。条件を満たした値は控えめなアクセントカラー、満たさない値はグレー、「算出不可」「判定不能」は区別できる別の表示にする。
- 左側に条件パネル、右側に結果テーブルを置く、スクリーナーでよく見るレイアウト。狭い画面では条件パネルを折りたたむ。
- ヒューリスティック判定には必ず「自動判定」のラベルを付け、根拠を1クリックで確認できるようにする。ユーザーに判定の確からしさを誤解させない。
- 保有状態の内訳は、一覧では1行に収まる小さな表示（区分ごとの比率を並べた小さな積み上げバーと数値など）にし、詳細では表で示す。
- 日本語 UI。日付は YYYY-MM-DD、金額は百万円または億円単位で表示し、単位を明記する。

## 用語と算出ルール（振る舞いの定義）
- **直近4期の売上CAGR（成長4年分）**: 直近の通期決算（実績）を含む連続した5つの通期売上高（FY0, FY-1, FY-2, FY-3, FY-4）から、CAGR = (FY0 / FY-4)^(1/4) − 1 で算出する。次の場合は「算出不可」とし、理由を表示する。
  - 直近5期の通期実績がそろわない場合
  - FY-4 の売上が0以下の場合
  - 5期のうちに、決算期変更による変則決算（12か月でない期間）を含む場合

  業績予想の値は使わない。
- **直近通期の営業利益率**: 直近の通期実績の営業利益 ÷ 売上高。営業利益が開示されていない場合（一部の IFRS 企業など）は「算出不可（営業利益の開示なし）」とする。
- **上場年数（推定）**: 保存済みの株価データで、その銘柄が最初に登場した日（初出日）から基準日（最新の取り込み日）までの年数。初出日が取得可能なデータ期間の開始日と同じ場合は、それより前から上場していた可能性があるため「データ期間開始以前から上場（N年超）」として扱い、「上場X年以内」の条件は満たさない。画面には「株価データの初出日からの推定」であることを明記する。
- **社長**: 直近の有価証券報告書の役員の状況で、役職名に「代表取締役社長」「代表取締役 社長執行役員」「代表執行役社長」「代表取締役CEO」などを含む人物。該当者が複数いる場合は全員を社長候補とする。
- **筆頭株主**: 直近の有価証券報告書の大株主の状況で、所有株式数の割合が最も大きい株主。
- **大株主上位**: 直近の有価証券報告書の「大株主の状況」に記載されている株主全員（通常は上位10名）。
- **オーナー系株主の区分**: 大株主上位の各株主を、次のどれか1つに分類する。複数に当てはまる場合は、上の区分を優先する。
  1. 社長本人: 氏名が社長の氏名と一致する個人
  2. その他の役員本人: 氏名が社長以外の役員の氏名と一致する個人
  3. 同姓の親族（推定）: 社長と同じ姓の個人で、1にも2にも当たらない人
  4. 資産管理会社（推定）: 社長の姓または氏名を名称に含む法人（例: 「株式会社ヤマダホールディングス」「有限会社山田興産」）
  5. オーナー系以外: 上のどれにも当たらない株主（信託口、金融機関、事業会社、その他の個人など）
- **保有状態の内訳**: 区分1〜4それぞれの持株比率の合計と、オーナー系合計比率（区分1〜4の合計）、筆頭株主の名前と比率。持株比率は有報に記載された「発行済株式（自己株式を除く）の総数に対する所有株式数の割合」を使う。
- **条件④の判定結果**: 「該当（社長が筆頭株主）」「該当（オーナー企業）」「非該当」「判定不能」の4つ。
  - 社長が筆頭株主: 筆頭株主の氏名が社長の氏名と一致する（空白・全角半角・旧字体を正規化して比べる）。
  - オーナー企業: オーナー系合計比率（区分1〜4の合計）が閾値（既定 20%、画面で変更可）以上。
  - 判定不能: 有報が未取得、大株主または役員の情報を抽出できなかった場合。
  - 判定結果には必ず根拠を保存する（筆頭株主の名前と比率、社長の名前と役職、保有状態の内訳、各株主の区分と分類理由、元の有報の書類ID・提出日）。

## 機能一覧

### F1: 認証とアクセス制御
- 概要: Supabase 認証によるログイン。全画面と全データ取得をログイン必須にし、許可されたメールアドレス以外は使えないようにする。
- ユーザーストーリー: 個人投資家として、自分だけがログインしてデータを見られるようにしたい。J-Quants の再配布禁止の規約を守る必要があるから。
- 受け入れ基準:
  - [ ] AC1.1 未ログインで任意のアプリ URL（`/`、スクリーニング画面、銘柄詳細画面など）にアクセスすると、ログイン画面にリダイレクトされる。
  - [ ] AC1.2 許可されたメールアドレスと正しいパスワードでログインするとダッシュボードが表示され、リロードしてもログイン状態が保たれる。
  - [ ] AC1.3 パスワードが間違っている場合は、日本語のエラーメッセージが表示され、ログインできない。
  - [ ] AC1.4 許可リストにないメールアドレスではアカウントを作れず、ログインもできない（画面に拒否メッセージが表示される）。ログイン画面に誰でも使える新規登録の導線はない。
  - [ ] AC1.5 ヘッダーのメニューからログアウトすると、ログイン画面に戻る。ブラウザの「戻る」で保護された画面に戻ってもデータは表示されない。
  - [ ] AC1.6 未ログインのままアプリのデータ取得用エンドポイントを直接リクエストすると、401 または 403 が返り、銘柄データは含まれない。
  - [ ] AC1.7 公開用のクライアントキーだけを使ってデータベースの市場データを読もうとしても、行は1件も返らない。
  - [ ] AC1.8 全画面のフッターに、データ出典（J-Quants / EDINET）と「投資助言ではない」旨の注記が表示される。
- 依存: なし

### F2: アプリシェルとダッシュボード
- 概要: ヘッダー、ナビゲーション（ダッシュボード、スクリーニング、ウォッチリスト、取り込み状況、設定）、テーマ切り替え、データの鮮度を表示するダッシュボード。
- ユーザーストーリー: ユーザーとして、ログインしたらすぐに「データがいつ時点のものか」を知りたい。古いデータで判断しないために。
- 受け入れ基準:
  - [ ] AC2.1 ログイン後、ナビゲーションから各画面に移動できる（まだ実装されていない画面は「準備中」ではなく、ナビゲーションに出さない）。
  - [ ] AC2.2 ダッシュボードに、最終取り込みの完了日時、保存済みの銘柄数、財務指標を算出できた銘柄数、条件④を判定できた銘柄数が表示される。いずれも保存済みデータから集計した実際の値である。
  - [ ] AC2.3 データが1件も無いときは、ダッシュボードに「まだデータが取り込まれていません」という空状態と、取り込み状況画面へのリンクが表示される。ダミーの数値は表示されない。
  - [ ] AC2.4 ライト／ダークのテーマを切り替えられ、リロードしても選択が保持される。
  - [ ] AC2.5 横幅 375px の画面でもナビゲーションが使え（ハンバーガーメニューなど）、表示が崩れない。
- 依存: F1

### F3: 取り込み基盤と銘柄マスタの取り込み
- 概要: Vercel Cron から毎日起動される取り込み処理の土台。最初の対象として J-Quants の上場銘柄一覧（コード、社名、市場区分、業種）を取り込む。取り込みの実行履歴と、データソースの接続状態を画面で確認でき、手動でも再実行できる。
- ユーザーストーリー: ユーザーとして、毎日自動でデータが更新され、失敗したら理由がわかるようにしたい。取り込みが止まっていることに気づかないと、古いデータで判断してしまうから。
- 受け入れ基準:
  - [ ] AC3.1 「取り込み状況」画面に、データソースごと（J-Quants、EDINET）の認証情報の設定状態（「設定済み」または「未設定」）が表示される。キーの値そのものは表示されない。
  - [ ] AC3.2 J-Quants のキーが未設定の環境で「今すぐ取り込み」を押すと、実行履歴に「失敗」として記録され、「J-Quants の API キーが設定されていません」と明示される。成功や0件成功としては記録されない。
  - [ ] AC3.3 実行履歴には、開始日時、終了日時、対象（銘柄マスタ、株価、財務、有報など）、結果（成功・一部失敗・失敗）、処理件数、エラーメッセージが新しい順に表示され、リロードしても残っている。
  - [ ] AC3.4 定期実行用のエンドポイントを、正しいシークレット無しで外部から呼び出すと拒否され（401 または 403）、取り込みは始まらず、実行履歴も増えない。
  - [ ] AC3.5 Vercel Cron で毎日1回（取引日の夜間など、J-Quants のデータ更新後）に実行されるよう設定されている。設定内容は契約書に記載し、デプロイ設定で確認できる。
  - [ ] AC3.6 （キーあり環境）取り込みが成功すると、銘柄マスタの件数が0件より多くなり、実行履歴に処理件数が表示される。
  - [ ] AC3.7 取り込み処理の実行中に「今すぐ取り込み」を押しても二重に実行されない（「実行中」と表示される）。
- 依存: F1, F2

### F4: 株価の初出日取り込みと上場年数の推定
- 概要: J-Quants の株価データから、銘柄ごとに初出日（株価データが最初に存在する日）を求めて保存し、上場年数を推定する。
- ユーザーストーリー: ユーザーとして、上場から日が浅い企業を見つけたい。上場直後の成長企業に投資機会があると考えているから。
- 受け入れ基準:
  - [ ] AC4.1 （キーあり環境）取り込み後、各銘柄に株価データの初出日と推定上場年数が保存され、取り込み状況画面にこの処理の実行結果が表示される。
  - [ ] AC4.2 データベースに初出日が「基準日の3年前」の銘柄を投入すると、推定上場年数は約3.0年と表示される。
  - [ ] AC4.3 初出日が取得可能なデータ期間の開始日と同じ銘柄は「データ期間開始以前から上場（N年超）」と表示され、年数が特定できないことがわかる。
  - [ ] AC4.4 2回目以降の取り込みでは、既に初出日が確定している銘柄の初出日は変わらない（新規上場銘柄だけが追加される）。
- 依存: F3

### F5: 財務データの取り込みと指標の算出
- 概要: J-Quants の決算データから通期の売上高と営業利益の実績を取り込む。直近5期の通期実績から「売上CAGR（成長4年分）」を、直近通期の実績から「営業利益率」を算出して保存する。算出できない場合は理由も保存する。
- ユーザーストーリー: ユーザーとして、高成長で利益率も高い企業を数値で絞り込みたい。成長と収益性を両立した企業を探しているから。
- 受け入れ基準:
  - [ ] AC5.1 データベースに通期売上 100 → 150 → 200 → 300 → 400（FY-4 → FY0）の銘柄を投入すると、売上CAGR は 41.4%（小数点以下1桁。(400/100)^(1/4) − 1）と表示される。
  - [ ] AC5.2 直近通期の売上 1,000、営業利益 120 の銘柄の営業利益率は 12.0% と表示される。
  - [ ] AC5.3 通期実績が4期分しかない銘柄は、CAGR が「算出不可（通期実績が5期未満）」と表示される。
  - [ ] AC5.4 FY-4 の売上が0以下の銘柄、直近5期に変則決算を含む銘柄、営業利益が開示されていない銘柄は、それぞれ理由付きの「算出不可」になる。
  - [ ] AC5.5 四半期決算や業績予想の値は、CAGR と営業利益率の算出に使われない（通期実績の値とのみ一致する）。
  - [ ] AC5.6 （キーあり環境）取り込み後、財務指標を算出できた銘柄数がダッシュボードに反映される。
  - [ ] AC5.7 算出ロジックには、上記のケースをすべて含む自動テストがあり、そのテストが通る。
  - [ ] AC5.8 通期実績が6期分以上ある銘柄では、直近5期だけが CAGR の算出に使われる（6期前の値を変えても CAGR は変わらない）。
- 依存: F3

### F6: スクリーニング画面（条件①〜③）
- 概要: 保存済みデータを対象に、売上CAGR、営業利益率、上場年数の3条件で銘柄を絞り込む。閾値は画面で変更でき、条件ごとにオン／オフを切り替えられる。結果は並べ替えられるテーブルで表示する。
- ユーザーストーリー: ユーザーとして、閾値を動かしながら該当銘柄の数と顔ぶれの変化をすぐ見たい。条件の厳しさを探りながら候補を絞るから。
- 受け入れ基準:
  - [ ] AC6.1 画面を開くと、既定値（CAGR ≥20%、営業利益率 ≥10%、上場5年以内）が条件パネルに入った状態で検索結果が表示される。条件①のラベルには「直近5期の通期実績から算出（成長4年分）」と注記がある。
  - [ ] AC6.2 条件ごとに閾値を数値入力（とスライダーなど）で変えられ、変えると結果の一覧と「該当 N 件」の表示が更新される。
  - [ ] AC6.3 CAGR 25% と 15% の2銘柄を投入した状態で CAGR の閾値を 20% にすると25%の銘柄だけ、15% にすると両方が表示される。
  - [ ] AC6.4 条件をオフにすると、その条件は絞り込みに使われない（オフにした条件の値で除外される銘柄が表示されるようになる）。
  - [ ] AC6.5 「算出不可」の銘柄を結果に含めるかどうかを選べる。既定では除外される。
  - [ ] AC6.6 結果テーブルには、コード、社名、市場区分、業種、売上CAGR、営業利益率、推定上場年数（初出日）、各条件を満たしているかの表示が並ぶ。列見出しをクリックすると昇順／降順で並べ替えられる。
  - [ ] AC6.7 条件と並べ替えの状態が URL に反映され、その URL をリロードしても同じ条件で表示される（URL を開けるのはログインした本人だけ）。
  - [ ] AC6.8 市場区分（プライム／スタンダード／グロース）と業種で追加の絞り込みができる。
  - [ ] AC6.9 該当が0件のときは「条件に一致する銘柄はありません」と表示される。データ自体が未取り込みのときは、別の空状態（取り込み状況画面へのリンク付き）が表示される。
  - [ ] AC6.10 結果が100件を超えるときはページ送りなどで全件をたどれる。
  - [ ] AC6.11 検索のたびに外部 API は呼ばれない（キー未設定の環境でも、保存済みデータがあれば検索できる）。
- 依存: F4, F5

### F7: 銘柄詳細画面
- 概要: 1銘柄の全情報を1画面にまとめる。基本情報、5期分の売上・営業利益の推移グラフと表、算出指標、初出日と推定上場年数、各条件の充足状況。
- ユーザーストーリー: ユーザーとして、スクリーニングで引っかかった銘柄について「なぜ引っかかったのか」を数値で確かめたい。算出の誤りや特殊な事情を見落とさないために。

  - [ ] AC7.2 通期5期分（FY-4〜FY0）の売上高と営業利益が表とグラフで表示され、値はデータベースに保存された値と一致する。保存済みの通期実績が5期に満たない場合は、ある分だけが表示され、足りない期は「データなし」と示される。
  - [ ] AC7.3 売上CAGR、営業利益率、推定上場年数が、算出に使った期（例: 「2021/03期 → 2025/03期（4年）」）と一緒に表示される。算出不可の場合は理由が表示される。
  - [ ] AC7.4 現在の閾値に対して各条件を満たすかどうかが、条件ごとに表示される。
  - [ ] AC7.5 存在しない銘柄コードの URL を開くと「銘柄が見つかりません」と表示される。

### F8: EDINET 有価証券報告書の取り込み（大株主・役員）
- 概要: EDINET API から各社の直近の有価証券報告書を探し、「大株主の状況」（氏名・名称、所有株式数の割合）と「役員の状況」（氏名、役職名）を抽出して保存する。J-Quants の銘柄とは証券コードで対応づける。
- ユーザーストーリー: ユーザーとして、経営者の持株状況を自分で有報を開かずに確認したい。全銘柄の有報を手で見るのは現実的でないから。
- 受け入れ基準:
  - [ ] AC8.1 EDINET のキーが未設定の環境で取り込むと、実行履歴に「EDINET の API キーが設定されていません」として失敗が記録される。J-Quants 側の取り込み結果には影響しない。
  - [ ] AC8.2 （キーあり環境）取り込み後、有報を取得できた銘柄の数が取り込み状況画面に表示される。
  - [ ] AC8.3 銘柄詳細画面に「大株主の状況」（順位、氏名・名称、持株比率）と「役員の状況」（氏名、役職名）が表示され、元の有報の書類ID、提出日、対象の事業年度、EDINET の書類閲覧ページへのリンクが付いている。
  - [ ] AC8.4 同じ会社に複数の有報（訂正報告書を含む）があるときは、最新の提出分が使われ、どの書類を使ったかが表示される。
  - [ ] AC8.5 抽出できなかった銘柄では、詳細画面に「有報から大株主／役員情報を抽出できませんでした」と理由が表示される。空の表だけを出すことはしない。
  - [ ] AC8.6 毎日の取り込みでは、前回以降に新しく提出された有報だけを処理し、処理済みの書類を毎回取り直さない（実行履歴の処理件数で確認できる）。
  - [ ] AC8.7 抽出ロジックには、実際の有報の形をしたテスト用フィクスチャ（個人株主、法人株主、信託口、役員の兼務表記を含む）を使った自動テストがあり、通る。
- 依存: F3, F7

### F9: 条件④ オーナー企業／社長筆頭株主の自動判定、保有状態の内訳、スクリーニングへの統合
- 概要: 大株主と役員を照合し、各大株主をオーナー系の区分（社長本人、その他の役員本人、同姓の親族（推定）、資産管理会社（推定）、オーナー系以外）に分類する。区分ごとの保有状態の内訳と、条件④の判定結果・根拠を保存する。スクリーニング画面に条件④と内訳の要約を加え、詳細画面に内訳の明細と判定根拠を表示する。
- ユーザーストーリー: ユーザーとして、経営者が大株主として利害を共有している企業だけに絞りたい。株主と経営者の利害が一致した企業を好むから。また、「誰がどの程度持っているか」を一覧でざっと見比べ、詳細では分類の理由を自分の目で確認したい。自動判定は間違うことがあるから。
- 受け入れ基準:
  - [ ] AC9.1 筆頭株主が「山田 太郎」、役員に「代表取締役社長 山田太郎」がいる銘柄は「該当（社長が筆頭株主）」と判定される（空白の有無や全角半角の違いがあっても一致する）。
  - [ ] AC9.2 筆頭株主が信託銀行（信託口）で、大株主上位に社長本人（8%）と「株式会社ヤマダホールディングス」（15%、社長の姓は山田）がいる銘柄は、オーナー系合計が 23% で既定の閾値 20% 以上なので「該当（オーナー企業）」と判定される。根拠には両方の株主と一致理由（「社長本人」「社長の姓を含む法人（資産管理会社と推定）」）が表示される。
  - [ ] AC9.3 大株主上位に役員や社長の関係者がいない銘柄は「非該当」になる。
  - [ ] AC9.4 有報が未取得、または抽出に失敗した銘柄は「判定不能」になり、理由が表示される。
  - [ ] AC9.5 スクリーニング画面に条件④が追加される。次の項目を画面で変えられ、変えると結果が更新される。
    - 判定モード（「社長が筆頭株主のみ」または「オーナー企業または社長が筆頭株主」）
    - オーナー企業と判定する合計持株比率の閾値（既定 20%）
    - 判定不能の銘柄を含めるかどうか
  - [ ] AC9.6 スクリーニング結果テーブルに条件④の判定結果の列があり、「自動判定」と明示されている。セルにマウスを乗せるかクリックすると、筆頭株主の名前と比率、社長の名前が表示される。
  - [ ] AC9.7 銘柄詳細画面の「条件④ 判定根拠」セクションに、筆頭株主（名前・比率）、社長（名前・役職）、一致した株主と一致理由、オーナー系合計比率、使った有報（書類ID・提出日・リンク）が表示される。
  - [ ] AC9.8 既定の4条件すべてがオンの状態で、4条件を満たすように投入した銘柄だけが一覧に表示される。
  - [ ] AC9.9 判定ロジックには、上記のケースと、社長が複数いるケース、旧字体（例: 髙／高、﨑／崎）の表記ゆれを含む自動テストがあり、通る。
  - [ ] AC9.10 （一覧の保有状態の要約）スクリーニング結果の各行に、保有状態の要約が1行で表示される。要約はオーナー系合計比率の数値と、区分ごとの比率を色分けした小さな積み上げバーなどで構成する。次の銘柄を投入すると、その行には「オーナー系 35.0%」と表示される。
    - 投入する銘柄の大株主: 社長「山田太郎」12.0%、個人「山田花子」5.0%、「有限会社山田興産」18.0%、信託口 9.0%
    - 要約にマウスを乗せるかクリックすると、次の内訳が表示される: 社長本人 12.0%、同姓の親族（推定）5.0%、資産管理会社（推定）18.0%、オーナー系合計 35.0%、筆頭株主 有限会社山田興産 18.0%
  - [ ] AC9.11 オーナー系の株主が1人もいない銘柄の要約は「オーナー系 0.0%」になり、筆頭株主の名前と比率は表示される。判定不能の銘柄の要約は「内訳なし（判定不能）」と表示される。
  - [ ] AC9.12 オーナー系合計比率の列で結果を昇順／降順に並べ替えられる。
  - [ ] AC9.13 （詳細の保有状態の内訳）銘柄詳細画面の「保有状態の内訳」セクションで、次の内容を確認できる。AC9.10 の銘柄では、4名の株主それぞれに正しい区分と分類理由が表示され、区分別の合計が一覧の要約と一致する。
    - 区分別の合計比率: 社長本人、その他の役員本人、同姓の親族（推定）、資産管理会社（推定）、オーナー系合計、オーナー系以外
    - 大株主上位の全員の明細: 順位、氏名・名称、持株比率、割り当てた区分、分類理由
    - 分類理由の例: 「社長『山田太郎』と氏名が一致」「社長と同姓『山田』の個人（親族と推定）」「社長の姓『山田』を名称に含む法人（資産管理会社と推定）」「役員『佐藤一郎（取締役CFO）』と氏名が一致」
  - [ ] AC9.14 社長以外の役員（例: 取締役 佐藤一郎 4.0%）が大株主にいる銘柄では、詳細の内訳でその株主が「その他の役員本人」に分類され、オーナー系合計に含まれる。
  - [ ] AC9.15 「同姓の親族（推定）」と「資産管理会社（推定）」の区分には「推定」のラベルが付き、推定であることの注記（「姓の一致による推定で、実際の親族関係・資本関係は確認していません」など）が詳細画面に表示される。
  - [ ] AC9.16 オーナー企業判定の閾値を 20% から 40% に変えると、AC9.10 の銘柄（オーナー系 35.0%）は「オーナー企業または社長が筆頭株主」モードの結果から外れる。30% に戻すと再び表示される。
- 依存: F8

### F10: 判定の手動補正
- 概要: 自動判定（条件④）が間違っているとき、ユーザーが銘柄ごとに判定を上書きし、メモを残せる。補正はユーザーごとに保存され、スクリーニングにも反映される。
- ユーザーストーリー: ユーザーとして、自分で有報を確認して誤判定だとわかった銘柄を直したい。同じ誤判定に何度も引っかかりたくないから。
- 受け入れ基準:
  - [ ] AC10.1 銘柄詳細画面で、条件④を「該当」「非該当」に手動で上書きし、理由のメモを入力して保存できる。
  - [ ] AC10.2 上書き後は、スクリーニング結果と詳細画面の両方で補正後の判定が使われ、「手動補正」のラベルと元の自動判定が並んで表示される。
  - [ ] AC10.3 補正を取り消すと、自動判定に戻る。
  - [ ] AC10.4 補正はリロードしても保持される。別の許可ユーザーでログインしたときは、その補正は見えず、影響もしない。
  - [ ] AC10.5 補正した後に新しい有報が取り込まれて自動判定が変わった場合、詳細画面に「補正後に自動判定が更新されました」と表示される。
- 依存: F9

### F11: 日次取り込みの信頼性（増分更新・再開・失敗の可視化）
- 概要: 全銘柄の取り込みを毎日確実に終わらせるための仕組み。実行時間の制限で途中で止まっても次の実行で続きから処理する。失敗した銘柄を記録し、データの鮮度が落ちていることを画面で警告する。
- ユーザーストーリー: ユーザーとして、取り込みが部分的に失敗しても全体が止まらず、何が古いままなのかを知りたい。気づかないうちにデータが欠けていると、スクリーニング結果を信用できなくなるから。
- 受け入れ基準:
  - [ ] AC11.1 取り込みが途中で中断された場合（時間切れなど）、実行履歴に「一部完了」と処理済み件数・残り件数が記録され、次の実行で残りの銘柄から処理が続く。
  - [ ] AC11.2 一部の銘柄だけ外部 API がエラーを返しても、他の銘柄の取り込みは続く。失敗した銘柄の一覧（コード、エラー内容）を実行履歴の詳細で確認できる。
  - [ ] AC11.3 最後に成功した取り込みから48時間以上たつと、全画面の上部に「データが古くなっています（最終更新: YYYY-MM-DD HH:mm）」という警告が表示される。
  - [ ] AC11.4 外部 API の呼び出し回数の制限を超えないよう、取り込みの速度が調整されている。制限に当たったときは待ってから再試行し、それでも失敗したらその旨が履歴に記録される。
  - [ ] AC11.5 取り込み中も、スクリーニング画面では前回までの完全なデータで検索でき、途中までのデータが混ざった結果にはならない。または、どの銘柄が更新中かが表示される。
  - [ ] AC11.6 上場廃止になった銘柄は、スクリーニング結果に出なくなる（詳細画面では「上場廃止」と表示される）。
- 依存: F3, F4, F5, F8

### F12: 条件プリセットの保存
- 概要: よく使う条件の組み合わせ（閾値、オン／オフ、市場・業種の絞り込み、並べ替え）に名前を付けて保存し、呼び出せる。既定の条件も自分好みに変えられる。
- ユーザーストーリー: ユーザーとして、「厳しめ」「グロース市場のみ」などの条件セットを切り替えたい。毎回閾値を入れ直すのは面倒だから。

  - [ ] AC12.3 プリセットの名前変更、上書き保存、削除ができる。削除前に確認ダイアログが出る。
  - [ ] AC12.4 1つのプリセットを「既定」にすると、スクリーニング画面を開いたときにその条件で表示される。
  - [ ] AC12.5 プリセットはユーザーごとに保存され、リロードや再ログインの後も残る。他のユーザーからは見えない。

### F13: ウォッチリストと新規該当銘柄の通知
- 概要: 気になる銘柄をウォッチリストに入れてメモを残せる。さらに、既定のプリセットで前回の取り込みから新しく条件を満たした銘柄、条件を満たさなくなった銘柄をダッシュボードに表示する。
- ユーザーストーリー: ユーザーとして、毎朝「今日新しく条件に入った銘柄」だけを確認したい。毎日一覧全体を見比べるのは大変だから。

  - [ ] AC13.1 スクリーニング結果と詳細画面から、銘柄をウォッチリストに追加・削除できる。追加済みかどうかがアイコンでわかる。
  - [ ] AC13.2 ウォッチリスト画面に、登録した銘柄の最新の指標、条件④の判定、メモ、追加日が表示される。メモは編集でき、リロードしても残る。
  - [ ] AC13.3 ダッシュボードに「新たに該当」「該当から外れた」銘柄が、直近の取り込み日と一緒に表示される。スクリーニング結果でも、新たに該当した銘柄に「NEW」バッジが付く。
  - [ ] AC13.4 前回の取り込み時点と今回とで、条件を満たすかどうかが変わるようにデータを投入すると、その銘柄が正しく「新たに該当」または「外れた」に分類される。
  - [ ] AC13.5 ウォッチリストはユーザーごとで、他のユーザーからは見えない。

### F14: AI による判定補助（オプション）
- 概要: 条件④の判定が難しい銘柄（法人株主が資産管理会社かどうか不明、社長の特定があいまいなど）について、LLM が有報の大株主・役員情報を読み、補助的な見立てと理由を日本語で示す。自動判定を置き換えるものではなく、参考情報として表示する。
- ユーザーストーリー: ユーザーとして、名前の一致だけではわからない関係（例: 社長の親族の資産管理会社）の手がかりがほしい。手動補正の判断材料になるから。
- 受け入れ基準:
  - [ ] AC14.1 銘柄詳細画面の判定根拠セクションに「AI に見立てを聞く」ボタンがあり、押すと、該当／非該当の見立て、理由、確信度（高・中・低）が表示される。

## スプリント計画
| Sprint | 対象機能 | ゴール（完了時にユーザーができること） |
|---|---|---|
| 1 | F1 認証とアクセス制御 | 許可されたメールアドレスでだけログインでき、未ログインでは画面にもデータにもアクセスできない |
| 2 | F2 アプリシェルとダッシュボード | ナビゲーションで画面を移動でき、ダッシュボードでデータの鮮度と件数（または未取り込みの空状態）を確認できる |
| 3 | F3 取り込み基盤と銘柄マスタ | データソースの接続状態と取り込み履歴を確認でき、手動と Cron で銘柄マスタを取り込める（キー未設定なら明示的なエラー） |
| 4 | F4 株価の初出日と上場年数 | 各銘柄の株価データの初出日と推定上場年数が保存・表示される |
| 5 | F5 財務データと指標の算出 | 直近5期の通期実績から売上CAGR（成長4年分）が、直近通期から営業利益率が算出され、算出不可の場合は理由付きで保存される |
| 6 | F6 スクリーニング画面（条件①〜③） | 3条件の閾値を画面で変えながら、保存済みデータから該当銘柄を検索・並べ替えできる（コアループ完成） |
| 7 | F7 銘柄詳細画面 | 結果から銘柄を開き、5期の業績推移と各条件の充足状況を確認できる |
| 8 | F8 EDINET 有報の取り込み | 各銘柄の大株主と役員の一覧を、出典の有報へのリンク付きで確認できる |
| 9 | F9 条件④の自動判定、保有状態の内訳、統合 | 4条件すべてでスクリーニングでき、一覧では保有状態の要約、詳細では大株主ごとの区分・分類理由と判定根拠を確認できる |
| 10 | F10 判定の手動補正 | 条件④の誤判定を自分で上書きし、メモを残し、スクリーニングに反映できる |
| 11 | F11 日次取り込みの信頼性 | 取り込みが中断・部分失敗しても続きから処理され、古いデータは警告される |
| 12 | F12 条件プリセット | 条件セットに名前を付けて保存・呼び出しでき、既定の条件を設定できる |
| 13 | F13 ウォッチリストと新規該当 | 気になる銘柄をメモ付きで管理し、毎日新たに該当した銘柄と外れた銘柄をダッシュボードで確認できる |
| 14 | F14 AI 判定補助（オプション） | 判定の難しい銘柄について、AI の参考見立てと理由を確認できる |

※ Sprint 1〜9 で、プロンプトの要求すべて（ログイン必須、4条件と閾値の変更、日次取り込み、保存済みデータの検索、判定根拠の表示）が満たされる。Sprint 10 以降は品質と体験を強化するスプリント。Sprint 14 は、ユーザーが LLM の利用を承認した場合だけ実施する。

## スコープ外
- データのエクスポート（CSV、Excel など）、公開の共有リンク、埋め込み、外部への通知配信（メール、Slack など）。J-Quants の再配布禁止に抵触するおそれがあるため。
- 株価チャート、テクニカル指標、リアルタイム株価、売買機能、証券口座との連携。
- 4条件以外のスクリーニング条件（PER、ROE、時価総額など）。ただし市場区分と業種の補助的な絞り込みは対象に含める。
- 有報以外の書類（大量保有報告書、臨時報告書など）を使った持株の更新。
- 役員の親族関係の正確な特定（同姓の推定と、AI の参考見立てまでにとどめる）。
- 誰でも登録できるマルチテナントの SaaS 化や課金機能。
- 英語 UI。
