### 重点確認（依頼の項目）

1. **insert の `user_id`**: トリガーは NULL のときだけ `auth.uid()` を入れる（マイグレーションの 69〜71 行）。
   - owner2 が owner の id を指定した insert は 403（`new row violates row-level security policy`）で拒否され、行は作られない。
   - `user_id` を省いた insert は owner の id で保存された（C6-4 の6）。
2. **トリガー関数の EXECUTE**: authenticated には EXECUTE が無い。`rpc/ownership_overrides_before_write` は 404 で、直接は呼べない。それでも書き込みのたびにトリガーが記録を求め直していることを確かめた（下の3）。
3. **C6-4（owner の JWT での PostgREST）**:
   - `auto_status`・`auto_owner_total_pct=99`・`auto_shareholders_doc_id=FAKE`・`created_at=2000-01-01` を偽った insert は、201 で `determined`・`30.00`・`SXTEST01`・`now()` として保存された。
   - 同じ値を偽った PATCH でも記録は変わらず、`created_at` は固定、`updated_at` は now になった。
   - `user_id`・`code` の変更は 42501 で拒否された。
   - `verdict=met` は insert・update とも 23514 で拒否された。
   - メモが空白・全角空白・改行・空・1,001・「𠮷」1,001 のときは 400 で拒否された。
   - 前後に空白のある「\n　前後　\n」は「前後」として保存された。「𠮷」1,000 個は受理された。
   - 空白への PATCH は拒否された。
   - authenticated の権限は DELETE・INSERT・SELECT・UPDATE の4つちょうどで、anon には列の権限も無い。
4. **textarea の maxlength**: 付いていない（`maxlength` 属性は null）。「𠮷」1,000 個を画面から保存できた。

## 改善提案（合格判定には影響しないが推奨）

- **m1（契約との小さなずれ）**: 契約の第4章は、`GET /api/screening` の行の `ownership.override` を「`<override>` から `auto_at_override` を除いたもの」としている。実装は `auto_at_override` と、契約に無い `auto_current` を含めて返す（詳細・書き込みの API も `auto_current` を返す）。値は正しく、害も無いが、契約の文面と違う。契約の形に合わせるか、CLAUDE.md の API の説明に `auto_current` を追記してほしい。
- **m2**: 条件④がオフのとき、④ の印の title が「条件④ …: オフ（手動補正）」になる。オフの条件は補正を使わないので、「（手動補正）」はオンのときだけ付ける方が誤解が無い。
- **m3（アクセシビリティ）**: 保存の後と、ダイアログからの取り消しの後に、フォーカスが `body` に落ちる（どちらも元のボタンが消えるため）。キーボードの利用者は区画の中の位置を失う。保存後は「編集」または補正後の判定へ、取り消し後は「判定を手動で補正する」へ、フォーカスを移すとよい。
- **m4**: 「確認済みにする」は `verdict = verdict` の update で記録を置き換えるため、`updated_at` が新しくなり、補正の欄に「更新 …」と出る。利用者は補正を編集していないので、「更新」は誤解を招く。記録を確かめた日時は、別の列（例 `acknowledged_at`）に分けることを推奨する。
- **m5**: 性能のテストの実測値（`console.log`）が vitest の設定で表示されず、記録が残っていない。閾値の検査には通っているが、次からは実測値を self-review に残せるようにしてほしい（例: `expect` のメッセージに値を含めるか、`--silent=false` で出す）。
- **m6（コード）**: `toApiOverride()` は、DB の値の形がスキーマと違うと黙って `null` を返す。GET の応答が `{"data": null}`（補正なし）になり、不整合が隠れる。形の違いは 500 にしてログを残す方が安全。
- **環境**: dev サーバーのメモリの閾値による再起動で、全件の E2E が1件ずつ落ちる状態が2スプリント続いている。対策の例:
  - E2E を本番相当のサーバーで流す手順を CLAUDE.md の標準にする（時計のずれの C6 など dev 専用の検査は dev で別に流す）。
  - dev サーバーのメモリの上限を上げる方法を調べる。
