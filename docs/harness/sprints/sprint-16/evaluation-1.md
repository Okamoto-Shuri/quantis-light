### B1: 段落が無い状態でも、見出しの横に「記載から引用。要約・言い換えはしていません」が出る（AC16.5 の未達）
- 重要度: Major
- 再現手順:
  1. `e2e/fixtures/business-description-example.sql` を投入する
  2. owner で `/stocks/9R005`（有報なし）を開く。9R006（取り込み待ち）・9R007（記載なし）・9R008／9R009（読み取れない）でも同じ
- 期待結果: AC16.5「段落を表示できない銘柄では…状態を明示する。**どの場合も、引用のラベル（AC16.3）は付けない**」。契約の第2章の6「`ok` 以外では、引用のラベルと段落の枠を出さない」。
- 実際の結果: 段落が無いすべての状態で、見出し「事業の内容」の横に「有価証券報告書（EDINET）の記載から引用。要約・言い換えはしていません」が出る。これは AC16.3 のラベル（「有価証券報告書『事業の内容』の冒頭の段落（原文のまま）」＝有報からの引用で、要約・言い換えではないことを示すもの）と同じ趣旨の文である。9R005 では「有報が未取得のため、事業の内容を表示できません」のすぐ上に「有価証券報告書の記載から引用」と書かれ、存在しない引用を示している。利用者には矛盾して見える。
- 根拠: 9R005 のセクションの innerText:
  `事業の内容 / 有価証券報告書（EDINET）の記載から引用。要約・言い換えはしていません / 有報が未取得のため、事業の内容を表示できません`
  ソースは `src/components/stocks/business-description-section.tsx` の `BusinessDescriptionSection`。次の部分が状態に関係なく描画される。
  ```tsx
  <p className="text-xs text-muted-foreground">有価証券報告書（EDINET）の記載から引用。要約・言い換えはしていません</p>
  ```
  E2E の C1-5 は testid だけを見ているので、この文を検出しない。
- 修正の方向: この文を `status === "ok"` のときだけ出す（または削除し、ok のラベルに任せる）。E2E の C1-5 に、ok 以外のセクションの文字に「引用」「原文のまま」「要約・言い換え」が含まれないことのアサーションを足す。

## 改善提案（合格判定には影響しないが推奨）
- m1: 取り込み状況のタイル「事業の内容を取得できた銘柄」の値「上場中の 11 銘柄のうち 6 銘柄」が、3列の幅で「…のうち／6 銘柄」と2行に折り返し、右寄せで読みにくい（スクリーンショットで確認。self-review の既知の問題2）。ほかのタイルと同じ「6 / 11 銘柄」の形にし、「上場中の…」を注記に回すと揃う。ただし AC16.9 の文言の形を保つ必要があるので、値を左寄せにするか、タイルを2列幅にする方法もある。
- m2: 読み込み中の骨組みに事業の内容の枠が無いので、本文が下にずれる（self-review の既知の問題1。並行作業の都合。スケルトンのコミット後に足すこと）。
- m3: HTML のソースの改行が和文の途中にあると、半角空白が入る（契約の規則どおり。実データの抜粋では見つかっていない）。キーを設定した後の実データで、和文の文字に挟まれた U+0020 が出る書類の数を一度確かめるとよい。
- m4: 取り込み待ち・失敗の状態の出典の行には、対象の事業年度が出ない（ok の出典には出る）。AC16.4 は ok の出典の要件なので違反ではない。ただし「どの年度の有報を待っているか」がわかると親切。
- 環境の注記（このスプリントの欠陥ではない）: 新しい worktree では、`next-env.d.ts`（git 管理外）が無いので、`pnpm build` の前の `pnpm typecheck` は `@/assets/quantis-icon.png` の型で失敗する。build の後は成功する。
