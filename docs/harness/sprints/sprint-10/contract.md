## 1. 対象機能

F9。有報（Sprint 8 で抽出済み）の大株主と役員を照合する。各大株主を、オーナー系の5つの区分（社長本人／その他の役員本人／同姓の親族（推定）／資産管理会社（推定）／オーナー系以外）のどれか1つに分類する。そのうえで、区分ごとの保有状態の内訳と、条件④の判定と根拠を保存する。

- スクリーニングに条件④を加える。判定モード・閾値・判定不能の扱いを画面で変えられるようにする。
- 一覧には、判定結果の列と保有状態の要約（数値と小さな積み上げバー）を加える。オーナー系合計比率で並べ替えられるようにする。
- 銘柄詳細には、「条件④ 判定根拠」と「保有状態の内訳」の2つの区画を加える。

これで既定の4条件すべてでスクリーニングできるようになる（スプリント計画の Sprint 10 の完了の定義）。

土台はすべて既存のものを使う。

| 使うもの | 出どころ |
|---|---|
| 使う書類の選び方（`annual_report_sections`）、大株主・役員の表（`annual_report_shareholders`・`annual_report_officers`） | Sprint 8 |
| 判定の式の1か所（`screening_evaluate`）、URL の状態（`lib/screening/params.ts`） | Sprint 6・7 |
| 先に作ってあるテーブル `ownership_judgments`、ダッシュボードの「条件④を判定できた銘柄数」 | Sprint 2 |

外部 API は新たに呼ばない。取り込み（target）も増やさない。判定は、保存済みの抽出結果から DB の中で求める（第2章の1）。

### 1. 判定の置き場所（DB の1か所。保存して、閾値は検索時に当てる）

- 分類と内訳は閾値に依存しない。したがって、銘柄ごとに1回求めて保存する（`ownership_judgments` を拡張し、株主ごとの明細は新しいテーブルに置く）。モード・閾値に依存する判定結果（4つのうちのどれか）は、検索のたびに `screening_evaluate` で求める。
- **分類の規則は DB の純粋な関数1か所**（名前の目安: `ownership_judgment_from_sections(p_shareholders jsonb, p_officers jsonb)`）。Sprint 5 の `financial_metrics_from_periods` と同じ形。大株主と役員の配列だけを受け取り、社長・筆頭株主・株主ごとの区分と理由・内訳を返す。書類や銘柄の情報は読まない。例外は、姓の読みの辞書（第2章の5）の参照だけ。
- 保存は `recalculate_ownership_judgments(p_codes text[])` が行う。`annual_report_sections` と同じ規則で使う書類を選び、上の関数を呼んで保存する。**銘柄で絞った形で書類を選び、全銘柄の区画を計算しない**（Sprint 8 の m5。第2章の9）。
- **再計算のトリガー**（文単位。同じトランザクションの中。Sprint 9 と同じ方式）:

  | 変更 | 再計算する銘柄 |
  |---|---|
  | `annual_report_extractions` の insert・update・delete | その書類の銘柄 |
  | `annual_report_shareholders`・`annual_report_officers` の insert・update・delete | その書類の銘柄 |
  | `edinet_documents` の insert・update（`withdrawn`・`withheld`・`sec_code`・`period_end`・`period_start`・`submitted_at`・`parent_doc_id`・`doc_type_code`）・delete | OLD と NEW の銘柄。訂正の子を持つ元の書類の変更では、子の銘柄も含む |
  | `stocks` の insert | その銘柄。upsert で既にある行は再計算しない（Sprint 9 と同じ） |

- こうすることで、取り込み（`save_edinet_extractions`）でも、評価者の直接の投入でも、同じ経路で判定が保存される。評価者は `ownership_judgments` に直接書かない。
- **画面と API は DB の値を表示するだけ**にする。アプリ側（TypeScript）で分類・合計・判定をしない。表示の文言（区分名・理由の文・判定結果のラベル）の組み立ては、`lib/ownership/display.ts`（名前は目安）の1か所で行う。

### 2. 名前の正規化（比較の鍵）

氏名・名称を比べるときは、次の順に正規化した文字列（比較の鍵）を使う。表示には元の記載を使う。

1. Unicode の NFKC。全角英数・半角カナ・全角空白・`㈱` などが、半角英数・全角カナ・空白・`(株)` になる。
2. **括弧の中を除く**: `(…)`・`[…]` とその中身を除く（例「山田 太郎（旧姓 鈴木）」→「山田 太郎」「山田 太郎（常任代理人 株式会社三菱UFJ銀行）」→「山田 太郎」）。法人か個人かの判定（第2章の4）は別の規則で行う（「（信託口）」は見るが、「（常任代理人 …）」は見ない）。
3. 空白（半角・全角・タブ・改行）をすべて除く。
4. **旧字体・異体字を新字体に置き換える**。最低限、次の組を持つ。

   | 旧字体・異体字 | 新字体 |
   |---|---|
   | 髙 | 高 |
   | 﨑・嵜 | 崎 |
   | 邊・邉 | 辺 |
   | 濵・濱 | 浜 |
   | 齋 | 斎 |
   | 齊 | 斉 |
   | 澤 | 沢 |
   | 櫻 | 桜 |
   | 廣 | 広 |
   | 國 | 国 |
   | 德 | 徳 |
   | 惠 | 恵 |
   | 榮 | 栄 |
   | 眞 | 真 |
   | 冨 | 富 |
   | 嶋・嶌 | 島 |
   | 槗 | 橋 |
   | 瀨 | 瀬 |
   | 證 | 証（S1。「野村證券株式会社」を「証券」として除く語に当てるため） |

   表は DB の関数の中の1か所に置く。組を増やすのはよい。減らさない。
5. 英字は大文字にする。
6. ひらがなはカタカナにする（読みの比較のため）。

- 氏名の一致は、比較の鍵が完全に等しいこと。部分一致では「本人」としない。
- 表示の中で名前を引用するとき（理由の文など）は、元の記載から空白だけを除いた形にする（例「社長『山田太郎』」「社長の姓『山﨑』」）。AC9.13 の例に合わせるため。照合と辞書の参照には、常に比較の鍵を使う（R3）。

### 3. 社長の特定 ★（ユーザー承認済み）

役職名は NFKC・空白と改行の除去・英字の大文字化・異体字の置き換えをしてから、次の規則で見る。

**除く語（R1）**: 役職名から、次の語を先に取り除いてから「社長」「頭取」「CEO」などを探す。「社長」「頭取」「CEO」が別の職の名の一部になっている語である。
- 副社長、副頭取、社長補佐、社長室、社長付、社長代行、社長代理、副CEO、CEO補佐
- 語の一覧は DB の関数の中の1か所に置き、単体テストで固定する。語を増やすのはよい。

1. **社長**: 除く語を取り除いた役職名が、「代表取締役」または「代表執行役」を含み、さらに「社長」「CEO」「最高経営責任者」「頭取」のどれかを含む役員。根拠は `title`。
   - 例（社長になる）:
     - 「代表取締役社長」
     - 「代表取締役 社長執行役員」
     - 「代表執行役社長」
     - 「代表取締役CEO」
     - 「代表取締役会長 兼 CEO」
     - 「代表取締役会長兼社長」
     - 「取締役頭取（代表取締役）」
   - 例（1 では社長にならない）:
     - 「代表取締役副社長」
     - 「代表取締役副頭取」（R1）
     - `"\n\n代表取締役\n\n\n専務執行役員\n\n\n社長補佐\n\n"`（S100W7OT の実際の形。R1）
     - 「取締役社長執行役員」（代表が無い。3 の対象）
     - 「代表取締役会長」
     - 「取締役CFO」
   - 該当者が複数いれば全員が社長候補（仕様）。
   - **「頭取」を含めた（ユーザー承認。副頭取は除く）**: 銀行の社長に当たる役職名である。業種で分けるのではなく、役職名の規則として扱う。
2. **代表者による補い（ユーザー承認）**: 1 に当たる役員が1人もいないときは、役職名に「代表取締役」または「代表執行役」を含む役員を全員、社長候補とする（例「代表取締役」だけの記載。新興企業に多い）。
   - 根拠は `representative`。画面には「役職名に『社長』等が無いため、代表取締役を社長として扱っています」と示す。
   - 社長の席が空いている会社では、代表取締役会長・副社長・専務も社長候補になる。その姓でも同姓・資産管理会社の推定が広がる。これは既知の制限として CLAUDE.md と self-review に書く。
3. **「取締役社長」などによる補い（S3）**: 1 にも 2 にも当たる役員がいないときは、除く語を取り除いた役職名が「社長」「頭取」「CEO」「最高経営責任者」のどれかを含む役員を、社長候補とする（例「取締役社長」）。
   - 根拠は `title_without_representative`。画面には「役職名に『代表』が無いため、『社長』等の役職の役員を社長として扱っています」と示す。
4. 1〜3 のどれにも当たる役員がいなければ、**判定不能**（理由 `president_not_found`。第2章の7。ユーザー承認）。
   - 社長がいないと、区分1・3・4と「社長が筆頭株主」がどれも判定できないため。

- 社長の**姓**は、社長ごとに次の順で決める。
  1. 役員の氏名の元の記載（NFKC 後）に空白があれば、最初の空白より前。連続した空白は1つの区切りとみなす（「宗政　　寛」→ 姓「宗政」。S5）。
     - **ただし（S2）**: 空白で区切った部分が3つ以上あり、すべて1文字のとき（例「山 田 太 郎」）は、この方法では決めない（2 へ進む）。
  2. 1 で決まらなければ、区分1で一致した大株主の氏名の元の記載について、1 と同じ方法で決める。
  3. どちらでも決まらなければ、姓は不明とする。その社長については、姓を使う推定を行わない。対象は、区分3と、第2章の5の照合規則2〜4。
     - 社長の氏名を名称に含む法人（第2章の5の照合規則1）は、姓が不明でも資産管理会社と推定する（R3。氏名の照合は姓を使わないため）。
     - 根拠に「社長『山田太郎』の姓を特定できないため、同姓の推定と、姓・読みによる資産管理会社の推定を行っていません」と示す。
     - 氏名の文字数から姓を推測することはしない。誤って別の姓と一致させないため。
  - 決めた姓は、**比較の鍵（第2章の2。異体字を置き換えた形）にしてから**、区分3の照合・辞書の参照・漢字の照合に使う（R3）。例: 「山﨑　健」の姓は、表示「山﨑」、比較の鍵「山崎」。辞書の読み「ヤマザキ」が見つかる。

  有報の XBRL の役員の氏名は、ふつう姓と名の間に全角空白がある。Sprint 8 のフィクスチャの実データ S100W7OT・S100W4KN・S100W5PD で確かめ、self-review に書く（C12-10）。

### 4. 個人と法人の区別

- 判定に使う文字列は、株主の氏名・名称に NFKC・異体字の置き換え・大文字化をしたもの。括弧は原則として残す（「（信託口）」を見るため）。
  - **ただし「常任代理人」で始まる括弧は、中身ごと除いてから判定する（R2）**。海外に住む株主の記載に付く「（常任代理人 株式会社三菱UFJ銀行）」の「株式会社」「銀行」で、個人が法人になるのを防ぐ。
  - 例: 「山田 太郎（常任代理人 株式会社三菱UFJ銀行）」は個人。「MSIP CLIENT SECURITIES（常任代理人 モルガン・スタンレーMUFG証券株式会社）」は、括弧の外の SECURITIES で法人のまま。
- その文字列が次の語のどれかを含めば **法人等**、含まなければ **個人** とする。
  - 日本語:
    - 株式会社、有限会社、合同会社、合資会社、合名会社、(株)、(有)
    - 法人（一般社団法人・財団法人・学校法人・医療法人・独立行政法人などを含む）、組合、基金、信託、銀行、証券、保険、生命、共済、金庫、公庫、持株会、ファンド、ホールディングス、政府、大臣
  - 英語（単語として。前後が英字でない位置）:
    - LIMITED、LTD、INC、CORP、CORPORATION、COMPANY、CO、LLC、LLP、LP、PLC
    - FUND、TRUST、BANK、SECURITIES、HOLDINGS、CAPITAL、PARTNERS、INVESTMENT、INVESTMENTS、MANAGEMENT、ACCOUNT、NOMINEES、NOMINEE
    - AG、SA、NV、BV、GMBH、MELLON
- **資産管理会社（区分4）の候補から除く法人等**: 次の語を含むもの（判定に使う文字列は上と同じ。「常任代理人」の括弧は見ない。異体字の置き換えで「證券」は「証券」になる。S1）。金融機関・信託口・持株会・公的機関は、社長の姓を含んでも資産管理会社と推定しない。
  - 信託、銀行、証券、保険、生命、共済、金庫、公庫、組合、基金、持株会、ファンド、政府、大臣
  - TRUST、BANK、SECURITIES、FUND、NOMINEE、NOMINEES、ACCOUNT、MELLON
  - 例:
    - 「山田工業取引先持株会」は区分5
    - 「株式会社ヤマダホールディングス」は区分4
- 語の一覧は DB の関数の中の1か所に置き、単体テストで固定する。語を増やすのはよい。

### 5. 資産管理会社（区分4）の照合と、姓の読みの辞書 ★（ユーザー承認済み）

AC9.2 の「株式会社ヤマダホールディングス」（社長の姓は「山田」）を資産管理会社と推定するには、漢字の姓とカタカナの名称を結び付ける必要がある。有報の XBRL の役員の氏名に読み（ふりがな）は無い。そこで、**姓の読みの辞書**を持つ。

- テーブル `public.surname_readings`（姓 → 読み。1つの姓に複数の読みがある。例: 山崎 → ヤマザキ・ヤマサキ、中島 → ナカジマ・ナカシマ）。
  - マイグレーションで入れる参照データで、市場データではない。
  - **日本の姓の上位 1,000 以上を収録し、よく使われる読みをすべて入れる**。出典（参照したランキング・資料の名前）をマイグレーションのコメントと self-review に書く。
  - アプリの画面に辞書の行を一覧で出すことはしない。
  - ローマ字（ヘボン式。例 ヤマダ → YAMADA、ヤマザキ → YAMAZAKI、オオノ → ONO と OHNO の両方）は、読みから関数で作る。辞書に持たなくてよい。
- 法人等（第2章の4。除く語を含まないもの）の名称の比較の鍵が、次のどれかを満たせば区分4とする。社長候補のだれか1人について満たせばよい。
  1. 社長の**氏名**（比較の鍵）を含む。理由は「社長の氏名『山田太郎』を名称に含む法人（資産管理会社と推定）」。**社長の姓が不明でも行う**（R3）。
  2. 社長の**姓**（比較の鍵）を含む。以下 2〜4 は姓が決まっている社長についてだけ行う。2文字以上の姓は名称のどこにあってもよい。1文字の姓（林・森など）は、名称から法人格の語（株式会社・有限会社・合同会社・(株)・(有) など）を除いた先頭にあるときだけとする（「株式会社森ビル」は一致、「株式会社青森物産」は一致しない）。理由は「社長の姓『山田』を名称に含む法人（資産管理会社と推定）」。
  3. 社長の姓の**読み**（カタカナ）を含む。読みが3文字以上のときだけ（「モリ」「イトウ」の2文字・3文字の差に注意。2文字の読みは誤一致が多いので使わない）。理由は「社長の姓『山田』の読み『ヤマダ』を名称に含む法人（資産管理会社と推定）」。
  4. 読みのローマ字（4文字以上）を**単語として**含む（前後が英字でない位置。例「YAMADA KOSAN CO., LTD.」）。理由は 3 と同じ形で、読みの欄にローマ字を示す。
  - 1〜4 の順に見て、最初に満たしたもので理由を決める。
- 辞書は、姓の比較の鍵（異体字を置き換えた形）で引く（R3）。辞書の姓も比較の鍵の形で持つ。
- 辞書に無い姓は、読み・ローマ字による照合をしない（漢字の姓・氏名による照合だけ）。これは既知の制限として CLAUDE.md と詳細画面の注記の説明に書く。
- **既知の制限（ユーザーの決定で記載）**: 3文字以上の読みでも、カタカナの外来語に含まれて誤って一致することがある（例: 新井「アライ」と「株式会社○○アライアンス」）。推定のラベルと注記で示すにとどめ、規則では防がない。CLAUDE.md と self-review に書く。C6-8 にこの例を「区分4になる（既知の制限）」として固定する。
- 辞書の範囲（上位 1,000 以上）と、読み・ローマ字の照合の長さの下限（3文字・4文字）は、ユーザーの承認を得た。

### 6. 区分の規則（まとめ）

大株主の各行を、上から順に見て最初に当たる区分に入れる。社長候補が複数いれば、どの社長について当たってもよい。

| 区分（コード） | 表示 | 条件 | 理由の例 |
|---|---|---|---|
| 1 `president` | 社長本人 | 個人で、比較の鍵が社長の氏名と等しい | 社長『山田太郎』と氏名が一致 |
| 2 `officer` | その他の役員本人 | 個人で、比較の鍵が社長以外の役員の氏名と等しい | 役員『佐藤一郎（取締役CFO）』と氏名が一致（役職名は改行を空白にする） |
| 3 `family` | 同姓の親族（推定） | 個人で、社長の姓が決まっており、次のどちらか。① 株主の氏名の元の記載に空白があり、最初の空白より前（比較の鍵）が姓と等しい。② 空白が無く、比較の鍵が姓で始まり、姓より長い（ただし姓が1文字のときは②を使わない） | 社長と同姓『山田』の個人（親族と推定） |
| 4 `asset_company` | 資産管理会社（推定） | 第2章の5 | 社長の姓『山田』を名称に含む法人（資産管理会社と推定） |
| 5 `other` | オーナー系以外 | 上のどれにも当たらない | 信託口・金融機関等（第2章の4の除く語を含む）／社長・役員の姓名を含まない法人／社長・役員と一致しない個人、の3通りの文 |

- 区分3・4は、画面で必ず「推定」のラベルを付ける（AC9.15）。
- 区分2の照合相手は、役員の状況の全員から社長候補を除いた人（取締役・監査役・執行役など、表にある全員）。

### 7. 判定と内訳

**筆頭株主**: 持株比率（`ratio_pct`）が最大の株主。同率が複数いれば全員を筆頭株主とする。表示は順位の最も小さい1名に「ほか N 名（同率）」を添える。

**判定の状態**（保存する。閾値に依存しない）:
- `determined`（判定できた）と `undeterminable`（判定不能）の2つ。
- 判定不能の理由は、次の順に最初に当たるもの。

| 理由のコード | 表示 |
|---|---|
| `no_annual_report` | 有報が未取得のため判定できません |
| `annual_report_pending` | 有報の本文が取り込み待ちで、処理済みの有報も無いため判定できません（書類 S…） |
| `shareholders_not_extracted` | 有報から大株主を抽出できなかったため判定できません（Sprint 8 の理由の文を添える） |
| `officers_not_extracted` | 有報から役員を抽出できなかったため判定できません（同上） |
| `president_not_found` | 役員の状況に社長（代表者）が見つからないため判定できません |

**使う書類（ユーザーの決定: 取り込み待ちの間は処理済みの直前の有報で判定する）**:
1. まず Sprint 8 の区画の選び方（`annual_report_sections`。対象の事業年度の候補を新しい順に見る）で、大株主・役員の区画ごとに書類を決める。大株主と役員で書類が違うこと（訂正に区画が無い場合）もある。その場合は根拠に両方の書類を示す。
2. **区画が未処理（pending）のときは、その区画について「処理済みの直前の有報」を使う**（S4: 大株主・役員の区画ごとに判断する。どちらか一方だけが pending なら、その区画だけを置き換える）。
   - 「処理済みの直前の有報」: その銘柄の有報・訂正有報（取り下げ・不開示でない、事業年度を決められるもの。Sprint 8 の候補と同じ条件で、**事業年度を対象の事業年度に限らない**）のうち、本文を処理済みで、その区画が `ok`・`invalid_values` の書類。事業年度の新しい順 → 提出日時の新しい順で最初のもの。`section_not_found`・`no_xbrl` の書類は飛ばす（Sprint 8 と同じ）。
   - 置き換えた区画は、根拠に「新しい有報（S…、YYYY-MM-DD 提出）は取り込み待ちです。処理済みの直前の有報（S…）で判定しています」と示す（`pending_doc_id` として保存する）。
   - 置き換える書類が無ければ、判定不能（`annual_report_pending`）。
3. Sprint 8 の詳細の「大株主の状況」「役員の状況」の表示は変えない（新しい有報の取り込み待ちを示したまま）。判定根拠の区画の注記で、判定に使った書類が違うことを示す。
- 銘柄マスタにあって有報の候補が無い銘柄は `no_annual_report`。`ownership_judgments` に行を作るか、行が無いことをそう扱うかは、ジェネレーターが決める。画面・API・ダッシュボードの数は同じになること。

**保存する根拠**（仕様の「判定結果には必ず根拠を保存する」）:
- 社長候補（氏名・役職名・根拠 `title`／`representative`／`title_without_representative`・姓の表示と比較の鍵、または姓が不明なこと）
- 取り込み待ちで置き換えた区画と、その取り込み待ちの書類ID（`pending_doc_id`）
- 筆頭株主（順位・氏名・比率・同率の人数）と、社長が筆頭株主か（`president_is_top_holder`）
- 区分ごとの比率の合計（1〜5）、オーナー系合計（1〜4）
- 株主ごとの区分・理由のコード・理由の文を組み立てる材料（一致した社長・役員の氏名と役職名、一致した姓・読み）
- 使った書類（大株主・役員それぞれの書類ID）と判定の日時
- 判定不能の理由

**比率の計算と表示**:
- 合計は numeric のまま足す（`ratio_pct` の十進の値。浮動小数点を経由しない）。
- 閾値との比較は、保存した値（丸める前）で `合計 >= 閾値` とする。閾値は小数点以下1桁までなので、「表示 ≥ X ⇔ 保存 ≥ X」が成り立つ。
- **表示の書式は2種類だけ**（R3）:

  | 書式 | 使う場所 |
  |---|---|
  | **百分率の小数点以下1桁に切り捨て**（例 35.00 → `35.0%`、19.98 → `19.9%`、18.00 → `18.0%`。Sprint 5 の財務指標と同じ方針） | 一覧のすべて（要約の「オーナー系 N%」、保有状態のポップオーバーの区分・合計・**筆頭株主の比率**、条件④のセルのポップオーバーの**筆頭株主の比率**）と、詳細の区分別の合計（`breakdown-totals`）・オーナー系合計（`evidence-owner-total`） |
  | **記載どおりの桁**（Sprint 8 の `formatRatioPct`。例 `12.00%`、`12.345%`） | 詳細の株主ごとの比率（`breakdown-holders` の明細、`evidence-top-holder`、`evidence-matches`、要約の1行）と、Sprint 8 の大株主の表 |

**判定結果**（検索のたびに、モードと閾値から求める）:

| 状態 | モード「オーナー企業または社長が筆頭株主」（`any`） | モード「社長が筆頭株主のみ」（`president`） |
|---|---|---|
| 判定不能 | 判定不能 → 条件④は `unavailable` | 同左 |
| 社長が筆頭株主 | 該当（社長が筆頭株主） → `met` | 該当（社長が筆頭株主） → `met` |
| 社長が筆頭株主でなく、合計 ≥ 閾値 | 該当（オーナー企業） → `met` | 非該当 → `unmet` |
| そのほか | 非該当 → `unmet` | 非該当 → `unmet` |

- 社長が筆頭株主で、合計も閾値以上のときは、「該当（社長が筆頭株主）」を出す（優先）。
- 結果のコードは `president_top`／`owner_company`／`not_matched`／`undeterminable`。
- 条件④がオフのときも、列には判定結果（既定のモード・その閾値での結果）を情報として出す。条件の印は「オフ」にする（①〜③と同じ）。

### 8. スクリーニングの条件と URL（Sprint 6 の規則に足す）

| パラメータ | 意味 | 値 | 既定 |
|---|---|---|---|
| `owner` | オーナー企業と判定する合計持株比率の閾値（%） | 0〜100。文法は既存の閾値と同じ（`^-?\d{1,4}(\.\d)?$`、範囲外は無効） | `20` |
| `ownermode` | 判定モード | `any`（オーナー企業または社長が筆頭株主）／`president`（社長が筆頭株主のみ） | `any` |
| `undeterminable` | 判定不能の銘柄を含める | `include`／`exclude` | `exclude` |
| `off` | 既存。`owner` を加える | `cagr,margin,years,owner` の部分集合 | なし |
| `sort` | 既存。`owner`（オーナー系合計比率）を加える | | `cagr` |

- **条件④の判定不能は、条件④の自分のスイッチ（`undeterminable`）だけで扱う。** 既存の「算出不可を含める」（`unavailable`）は、条件①〜③の算出不可・未確定だけに効く（AC9.5 が条件④に独立の項目を求めているため）。
  - 結果に含まれる行 = どのオンの条件にも `unmet` が無く、①〜③の `unavailable` は `unavailable=include` のときだけ、④の `unavailable` は `undeterminable=include` のときだけ許す。
  - 除外の件数は2つに分けて返す（`excludedUnavailable`（既存。①〜③）と `excludedUndeterminable`（④だけの理由で除いた数））。画面は「判定不能のため除外: N 件」を既存の表示の隣に出す。
- `ownermode=president` のとき、閾値の入力は無効（disabled）にする。「『社長が筆頭株主のみ』では使いません」と示す。URL の `owner` は保つ。
- **正規形のクエリ**の順番: `cagr, margin, years, owner, ownermode, off, unavailable, undeterminable, market, sector, sort, order, page`。
  - `owner`・`ownermode` は、ほかの閾値と同じく常に書く。
  - `undeterminable` は `include` のときだけ書く。
  - 既存の URL（`owner`・`ownermode` の無いもの）は既定値で解釈する。つまり条件④はオン。これは仕様（既定の4条件がオン）どおりの変化である。
- 並べ替え `sort=owner`: 保存したオーナー系合計（丸める前）で並べる。初めて選んだときは降順。判定不能は昇順・降順とも常に最後。同じ値はコード順（既存の規則）。
- 画面（lenient）は不正な項目を既定値にして注記し、API（strict）は 400 `invalid_params`（既存の規則）。
- 銘柄詳細のクエリ・戻り先（Sprint 7）も同じパラメータを持ち回る（`detailConditionsFromParams` は `parseScreeningParams` を使うので、同じ関数で扱う）。

### 9. 性能（Sprint 8 の m5 を含む）

- `screen_stocks` は、判定を保存した表を結合するだけにする。検索のたびに名前の正規化や照合をしない。
- 再計算は、指定した銘柄の書類だけから区画を選ぶ（関数に銘柄を渡す、またはビューの述語が銘柄で絞れる形にする）。
  - Sprint 8 の `annual_report_detail(code)` も同じ形にして、全銘柄の区画を計算しないようにする。
  - `annual_reports_summary()` は全銘柄を数えるので、全件の計算のままでよい。
- 目標は C12-1。
