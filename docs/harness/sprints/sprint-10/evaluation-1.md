### 想定外の既存テストの変更 A〜C の判断

- **A（edinet.spec の 375px）**: 妥当。旧いアサーション「表が枠からはみ出す」は、C10-5（持株比率が横スクロールせずに見える）と両立しない。置き換え後も、枠が `overflow-x: auto` であることは確かめている。
- **B（stock-detail の既定の条件）**: 妥当。既定の条件の意味が仕様どおり変わったので、①〜③の意図を保つために `off=owner` を付けた。これで表示が「スクリーニングの条件で判定しています」に変わるのは必然である。なお「既定の条件で判定しています」は、評価者が `/stocks/9U006` で表示されることを確かめた。
- **C（stock-detail の API の既定の条件）**: 妥当。既定で `included: false`・`owner: "unavailable"` になることを確かめたうえで、`off=owner` の場合も加えている。むしろ仕様の変化を正しく固定している。

## 改善提案（合格判定には影響しないが推奨）

- **m1（375px の内訳の明細の氏名の列）**: `/stocks/9U006` の `breakdown-holders` で、氏名・名称の列が約 3〜4 文字の幅しかない。「日本マスタートラスト信託銀行株式会社（信託口）」が7行に折り返す。
  - 契約の要件（比率と区分が見える）は満たしているが、読みにくい。
  - 分類理由を区分の下に出している分、区分の列が広い。名称の列に幅を回す（例: 375px では順位の列を名称の左に詰める、区分の列の最小幅を下げる）ことを勧める。
- **m2（一覧のバー）**: 幅 40px なので、5% の区分は 2px しかない。要約の数値とポップオーバーで補っているので実害は小さいが、色の区別はほぼ読み取れない。幅に余裕のある画面ではバーを広げることを勧める。
- **m3（姓の読みの辞書）**: 主な読みは正しい（抜き取り 120 姓で誤りは見つからなかった）。ただし、契約の「よく使われる読みをすべて」に対して、別の読みの抜けがある。
  - 例: 岩崎（イワザキ）、宮崎（ミヤサキ）、中沢（ナカサワ）、小島（オジマ・コシマ）、塩谷（シオタニ・エンヤ）、清野（キヨノ）。
  - 抜けは「推定しない」側に倒れるので誤判定にはならない。ただし、出典との照合を次のスプリントで行うことを勧める。
- **m4（閾値 0）**: `owner=0` では、オーナー系 0.0% の銘柄（9U003）も「該当（オーナー企業）」になる。規則（合計 ≥ 閾値）どおりだが、利用者には不自然である。閾値の下限を 0.1 にするか、0% のときは「オーナー企業」にしない、などを検討してほしい。
- **m5（判定不能の根拠の「使った有報」）**: 9U013（本文が未処理）の判定根拠に「使った有報 SXTEST13」と出るが、実際には使っていない。判定不能のときは「対象の有報」などの見出しにすると誤解がない。
- **m6（区分名の表記の揺れ）**: 一覧のポップオーバーは「資産管理会社（推定）」、詳細は「資産管理会社」＋「推定」のバッジで、表記が違う。AC9.13 の「一致」の趣旨から、どちらかにそろえるとよい。
- **環境（dev）**: E2E を全件流した後の dev サーバーが、メモリの閾値で再起動した（`approaching the used memory threshold, restarting`）。その間の `/imports` への要求が1回 30 秒でタイムアウトした。self-review にも記載があり、アプリの不具合ではない。ただし、E2E の不安定の原因になりうるので、CLAUDE.md に一言あるとよい。
- **コード**: `ownership_name_key` などに `set search_path` が無い。anon・authenticated には実行権限が無く、中で使うのも組み込みの関数だけなので、リスクは低い。advisor の警告を避けたいなら、`search_path = pg_catalog` を付けたうえでインライン展開が保たれるか計測するとよい。
