# Sprint 02 自己評価（ラウンド 1）

## 実装内容

### 契約（改訂1・改訂2）
- contract-review.md の R1〜R5 と注意事項を反映した（改訂履歴に記載）。
  - 投入例の日時は `now()` からの相対にした。
  - 相対表記の規則（未来は「たった今」）を定めた。
  - コントラストは WCAG AA の数値で判定する。
  - 設定画面の「アカウント」と、実行履歴が0件のときの表示を決めた。
  - 集計の失敗は、実際の画面で確かめる手順にした。
  - API のキー名を確定させた。
  - B2' が解消できなかったときの扱いを決めた。
- 改訂2（実装時）: API の `lastCompletedRun` に `status` を追加した。追加のみで、条件の削除や緩和は無い。

### DB（`supabase/migrations/20260925000000_dashboard_tables.sql`）
- 3つのテーブルを追加した。
  - `public.ingestion_runs`: `status` と `finished_at` の整合、および `finished_at >= started_at` を制約で保証する。
  - `public.financial_metrics`: 値と「算出不可の理由」のどちらか一方だけを持つ（XOR 制約）。
  - `public.ownership_judgments`
- 3つとも `stocks` と同じ方針にした。RLS を有効にし、anon の権限は無し。select は許可リストに入った authenticated だけ、書き込みは service_role のみ。
- `public.dashboard_summary()` を追加した。
  - security invoker なので RLS が効く。
  - 1回の問い合わせで、全件数・最終完了・直近の実行を返す。
  - 実行権限は authenticated と service_role だけ。

### 画面
- アプリシェル
  - ヘッダーに次を置いた。
    - 横並びのナビゲーション（`src/lib/navigation.ts` の `NAV_ITEMS` で1か所に定義）
    - テーマボタン
    - アカウントメニュー
  - 768px 未満では、ナビゲーションをメニューボタンで開くドロワー（shadcn Sheet）に切り替える。
  - 現在の画面の項目には `aria-current="page"` と下線（ドロワーでは左の線）を付ける。
- テーマ
  - Cookie `theme` に保存し、ルートレイアウトがサーバー側で `<html data-theme>` を出力する。
  - ヘッダーのメニューと設定画面のラジオは、`<html data-theme>` を唯一の状態とし、`useSyncExternalStore` と `MutationObserver` で同期する。
  - Cookie の不正な値は `system` として扱う。
- ダッシュボード `/`: 集計の結果に応じて3つの表示に分かれる。
  - 空状態（銘柄0件）
  - 通常: データの鮮度（最終完了、直近の実行）と件数タイル3つ（割合のメーター、財務の内訳付き）
  - 集計エラー
- 取り込み状況 `/imports`: 実行履歴の閲覧だけ。
  - 768px 以上は表、それ以下はカード形式。
  - 最大 50 件で、51 件以上あるときは注記を出す。
  - 0件のときは空状態。
  - 取得に失敗したときはエラー表示。
- 設定 `/settings`: テーマの3択と、アカウント（メールアドレス、許可の状態、最終ログイン。すべて実際のセッションの値）。
- API: `GET /api/dashboard`。`requireApiUser` で保護し、`jsonNoStore` で返す。集計が失敗したら 500 `{"error":"internal_error"}`。
- 404（B2' の対策）
  - 一致しない URL は `(app)/[...missing]/page.tsx` が `notFound()` を呼び、同期コンポーネントの `(app)/not-found.tsx` が保護レイアウトの中で描画する。
  - ルートの `not-found.tsx` は、同期で認証の無い最小限のものにした（保護画面の外で `notFound()` を呼んだときだけ使われる）。
- 配色トークン: `signal-strong`、`caution*`、`destructive-muted/strong` を追加した（淡い背景の上の文字が 4.5:1 を満たすようにするため）。

## 既知の問題・未実装
- 取り込み状況の画面は実行履歴の閲覧だけ。データソースの状態、「今すぐ取り込み」、Cron は Sprint 3 で作る（契約の第2章と第8章）。現時点では、アプリ自身が `ingestion_runs` に行を書く経路は無い。
- 実行履歴の表は、768px 以上では画面幅に合わせて列が折り返す。エラーメッセージが非常に長い場合は、その列の中で折り返す。
- 取り込み状況の画面とダッシュボードの一部は、768px 未満と以上で別の DOM（カードと表、またはドロワーと横並び）を出し分けている。見えない側は `display: none` なので支援技術には読まれないが、`page.getByText` で探すと、表示されていない側の要素も一致しうる。
- 「最終取り込みの完了日時」は、どの対象でも、成功または一部失敗で終わった最新の実行を指す。日次取り込みの全体をどう定義するかは、Sprint 3 以降で見直す（契約の論点3）。
- `ownership_judgments.status` は、Sprint 9 で判定結果の4区分と重複させないよう整理が必要（レビューでの注意）。
