# Sprint 06 契約: F6 スクリーニング画面（条件①〜③）

## 1. 対象機能

F6 スクリーニング画面。保存済みのデータ（銘柄マスタ、株価の初出日、財務指標）だけを対象に、次の3条件で銘柄を絞り込む。
- 条件① 売上CAGR（直近5期の通期実績から算出。成長4年分）≥ X%
- 条件② 営業利益率（直近通期）≥ Y%
- 条件③ 上場 Z 年以内（株価データの初出日からの推定）

閾値は画面で変えられ、条件ごとにオン／オフできる。「算出不可」の銘柄を含めるかどうか、市場区分と業種による追加の絞り込み、列見出しでの並べ替え、100件ごとのページ送りを備える。状態はすべて URL に持つ。新しい画面 `/screening` をナビゲーションの2番目（ダッシュボードの次）に加える。

ここでコアループ（閾値を動かす → 該当件数と顔ぶれが変わる）が完成する。銘柄詳細（Sprint 7）はまだ無いので、結果の行はリンクにしない。

### 仕様書の受け入れ基準（引用）

- AC6.1 画面を開くと、既定値（CAGR ≥20%、営業利益率 ≥10%、上場5年以内）が条件パネルに入った状態で検索結果が表示される。条件①のラベルには「直近5期の通期実績から算出（成長4年分）」と注記がある。
- AC6.2 条件ごとに閾値を数値入力（とスライダーなど）で変えられ、変えると結果の一覧と「該当 N 件」の表示が更新される。
- AC6.3 CAGR 25% と 15% の2銘柄を投入した状態で CAGR の閾値を 20% にすると25%の銘柄だけ、15% にすると両方が表示される。
- AC6.4 条件をオフにすると、その条件は絞り込みに使われない（オフにした条件の値で除外される銘柄が表示されるようになる）。
- AC6.5 「算出不可」の銘柄を結果に含めるかどうかを選べる。既定では除外される。
- AC6.6 結果テーブルには、コード、社名、市場区分、業種、売上CAGR、営業利益率、推定上場年数（初出日）、各条件を満たしているかの表示が並ぶ。列見出しをクリックすると昇順／降順で並べ替えられる。
- AC6.7 条件と並べ替えの状態が URL に反映され、その URL をリロードしても同じ条件で表示される（URL を開けるのはログインした本人だけ）。
- AC6.8 市場区分（プライム／スタンダード／グロース）と業種で追加の絞り込みができる。
- AC6.9 該当が0件のときは「条件に一致する銘柄はありません」と表示される。データ自体が未取り込みのときは、別の空状態（取り込み状況画面へのリンク付き）が表示される。
- AC6.10 結果が100件を超えるときはページ送りなどで全件をたどれる。
- AC6.11 検索のたびに外部 API は呼ばれない（キー未設定の環境でも、保存済みデータがあれば検索できる）。
- AC6.12 （改訂2で追加。上場前の期の補完（F15）が入るまでの暫定の注記）条件①の近く（条件パネルの条件①の説明、または結果一覧の上）に、「上場から約4年未満の銘柄は、上場前の期のデータがまだ無いため通期実績が5期に満たず、条件①（売上CAGR）を算出できません」という趣旨の注記が常に表示される。注記は画面を開いた直後から、スクロールや操作なしで条件①と一緒に見える位置にある。
- AC6.13 （改訂2で追加）通期実績が3期分しか無い銘柄を投入し、「算出不可を含める」をオンにすると、その銘柄の売上CAGR 欄は「算出不可（通期実績が5期未満）」と表示され、AC6.12 の注記と矛盾しない。

### 持ち越し事項の扱い

- **Sprint 4 評価の m4（性能）**: スクリーニングの絞り込み・並べ替え・件数の集計では、ビュー `stock_listing_ages`（行ごとに plpgsql 関数を評価する）を使わない。条件③は「閾値 Z から初出日の下限日を1回だけ求め、`first_price_date` の比較にする」形にし、推定上場年数の表示用の値は、そのページに出す行（最大100行）だけで求める（第2章の4）。財務は `financial_metrics` の `revenue_cagr`・`operating_margin`（索引あり）を直接比べる。性能の完了条件を C11 に置く。
- **ユーザーの決定（金融業）**: 銀行などの金融業をスクリーニングの対象から除外しない。除外のフィルタも作らない。銀行は `Sales` に経常収益が入るので売上CAGR は算出され、営業利益（`OP`）が空なので営業利益率は「算出不可（営業利益の開示なし）」になる。この振る舞いはそのまま使う。算出不可の銘柄の扱いは第2章の3のとおり（既定では条件②を満たさない扱いで除外、「算出不可を含める」で表示）。
- **Sprint 5 評価の任意の改善（D1〜D3、注記、Q1、Q2）**: 第2章の9と C13 のとおり実施する。未実施のものがあれば self-review に明記し、合否には含めない（実施したものは C13 で確かめる）。

## 2. 仕様上の論点と、このスプリントでの解釈

評価者は、この解釈が妥当かも判断してほしい。

1. **閾値の意味と比較（「表示 ≥ X ⇔ 保存 ≥ X/100」「表示 ≤ Z ⇔ 正確 ≤ Z」）**
   - 閾値は小数点以下1桁までの数値で受け付ける（`20`、`20.5`、`-5`）。2桁以上は入力エラー。
   - 条件①: `revenue_cagr >= X / 100`。条件②: `operating_margin >= Y / 100`。どちらも「以上」。
     - 閾値は DB に**十進の文字列**で渡し、`numeric` で割る（浮動小数点を経由しない。`20.3` → `0.203` が正確になる）。
     - 表示（`*_display_pct`）は百分率の小数点以下1桁に切り捨てなので、小数点以下1桁の X に対して「表示 ≥ X ⇔ 保存 ≥ X/100」が成り立つ（Sprint 5 の設計）。例: 保存 0.2 → 表示 20.0% → X=20 で満たす。保存 0.1999855321 → 表示 19.9% → X=20 で満たさない。
   - 条件③: 「上場 Z 年以内」は `listing_years_exact <= Z`（丸める前の正確な値）。境界を含む。
     - 表示は小数点以下1桁に切り上げ（Sprint 4）なので、小数点以下1桁の Z に対して「表示 ≤ Z ⇔ 正確 ≤ Z」が成り立つ。例: 初出日 2021-09-24、基準日 2026-09-24 → 正確 5.0、表示 5.0年 → Z=5 で満たす。初出日 2021-09-23 → 正確 5.0027、表示 5.1年 → 満たさない。
     - 「データ期間開始以前から上場」（`first_price_date = data_start_date`）の銘柄は、Z の値にかかわらず満たさない（仕様の用語定義）。
2. **閾値の範囲と既定値**
   | 条件 | 既定 | 入力できる範囲 | スライダーの範囲・刻み |
   |---|---|---|---|
   | ① 売上CAGR ≥ X% | 20 | −100.0〜1,000.0 | 0〜100、1 |
   | ② 営業利益率 ≥ Y% | 10 | −100.0〜100.0 | 0〜50、1 |
   | ③ 上場 Z 年以内 | 5 | 0.1〜10.0 | 0.5〜10、0.5 |
   - スライダーの範囲外の値も数値入力では入れられる（スライダーは端に張り付く）。範囲外・空・数値でない・小数点以下2桁以上の入力は、入力欄の下にエラー（例: 「−100〜1000 の数値を小数点以下1桁までで入力してください」）を出し、結果は更新しない（直前の有効な条件のまま）。
   - 画面の入力欄では、前後の空白を除き、全角の数字・マイナス・小数点を半角に直してから（NFKC）、第2章の6の閾値の文法で検証する（日本語入力のまま数字を打っても通るようにするため）。URL と API ではこの変換をせず、文法どおりに厳密に検証する。
   - 条件③の上限を 10.0 にするのは、株価のデータ期間（Standard で10年）より長い年数は判定できないため。
3. **「算出不可」の扱い（AC6.5・AC6.13）**
   - 条件ごとの状態を次の4つで表す。
     | 状態 | 意味 |
     |---|---|
     | 満たす（`met`） | 値があり、閾値の条件を満たす |
     | 満たさない（`unmet`） | 値があり、満たさない。**条件③の「データ期間開始以前から上場」もここ**（仕様の用語定義により「上場X年以内」の条件を満たさないと定められているため。値が無いのではなく、条件の判定が定義で決まっている） |
     | 算出不可（`unavailable`） | 値が無い。条件①②: `financial_metrics` の理由コードがある、または財務データが無い（行が無い）。条件③: 初出日が未確定（行が無い）、または基準日が無い |
     | オフ（`off`） | その条件はオフで、絞り込みに使っていない |
   - **既定（「算出不可を含める」がオフ）**: オンの条件のどれかが `unmet` または `unavailable` なら除外する。つまり、算出不可の値は「その条件を満たさない」扱い。
   - **「算出不可を含める」がオン**: オンの条件のどれかが `unmet` なら除外する。`unavailable` は除外しない（その条件については判定できないものとして一覧に残し、状態を「算出不可」と表示する）。
   - オフの条件は、状態にかかわらず絞り込みに使わない（AC6.4）。
   - 「算出不可を含める」は、条件ごとではなく1つのスイッチにする（仕様どおり）。
   - 金融業の扱いは第1章のとおり（特別扱いしない）。スイッチの説明文に「銀行など営業利益を開示しない会社は、営業利益率が算出不可になります」と書く。
4. **性能の設計（m4）**
   - 絞り込み・件数・並べ替え・ページの切り出しを、DB 関数1回（`public.screen_stocks(jsonb)`。security invoker、authenticated と service_role が実行可。RLS がそのまま効く）で行い、結果を jsonb で返す（PostgREST の `max_rows = 1000` を受けない）。
   - 条件③: 基準日 R と閾値 Z から「`listing_years_exact(F, R) <= Z` となる最も古い初出日 F_min」を**1回だけ**求め、`first_price_date >= F_min and first_price_date > data_start_date` で比べる。年数は初出日について単調（初出日が新しいほど年数は小さいか等しい）なので、この比較は `listing_years_exact <= Z` と一致する。一致することを、境界の日付を網羅する自動テストで確かめる（C10-3）。
   - 並べ替え「推定上場年数」も、年数ではなく初出日で並べる（年数の昇順 = 初出日の降順）。
   - 表示用の年数（`estimated_listing_years`、`listing_years_exact`、`listing_years_lower_bound`）は、そのページの行（最大100行）だけで `listing_years_between` を呼んで求める。表示の値は Sprint 4 のビューと同じ関数から出るので、`/imports` や `GET /api/stocks` の値と一致する。
   - `stock_listing_ages` ビューと `/imports` の区画は変えない（行ごとの評価は `/imports` の表示だけに残る。規模は Sprint 4 の評価で許容済み）。
5. **並べ替え**
   - 並べ替えられる列: コード、社名、市場区分、業種、売上CAGR、営業利益率、推定上場年数。条件の充足の列は並べ替えない。
   - 列見出しのボタンを押すと、その列で並べ替える。同じ列をもう一度押すと昇順／降順が入れ替わる。別の列を初めて押したときの向きは、売上CAGR・営業利益率は降順、推定上場年数・コード・社名・市場区分・業種は昇順。
   - 既定は売上CAGR の降順。
   - 値の無い行（算出不可・財務データなし・初出日が未確定）は、**昇順でも降順でも最後**に置く。同じ値の行はコードの昇順。
   - 推定上場年数の順: 昇順は「年数の分かる銘柄（年数の小さい順 = 初出日の新しい順）→ データ期間開始以前から上場の銘柄（データ期間の開始日の新しい順）→ 未確定」。降順は「データ期間開始以前 → 年数の大きい順 → 未確定」。
   - 市場区分は市場コード（`0111` プライム → `0112` スタンダード → `0113` グロース）の順、業種は33業種コードの順、社名は DB の既定の照合順序。
   - 見出しには現在の並びを矢印のアイコンで示し、`aria-sort` を付ける。
6. **URL（AC6.7）**
   | パラメータ | 値 | 既定（省略時） |
   |---|---|---|
   | `cagr` | 条件①の閾値（%） | `20` |
   | `margin` | 条件②の閾値（%） | `10` |
   | `years` | 条件③の閾値（年） | `5` |
   | `off` | オフにした条件をカンマ区切りで（`cagr`、`margin`、`years`） | なし（すべてオン） |
   | `unavailable` | `include` で「算出不可を含める」 | 除外 |
   | `market` | 市場コードをカンマ区切りで（`0111`、`0112`、`0113`） | なし（すべての市場） |
   | `sector` | 33業種コードをカンマ区切りで | なし（すべての業種） |
   | `sort` | `cagr`、`margin`、`years`、`code`、`name`、`market`、`sector` | `cagr` |
   | `order` | `asc`、`desc` | 列ごとの既定（第2章の5） |
   | `page` | 1 から始まるページ番号 | `1` |
   - 画面で操作すると、URL を `router.replace` で書き換える（閾値の入力のたびに履歴を増やさない）。**操作の後の URL には、条件のパラメータ（`cagr`、`margin`、`years`、`sort`、`order`）を常に明示的に書く**（既定値でも省略しない）。`off`・`unavailable`・`market`・`sector` は該当するときだけ、`page` は 2 以上のときだけ書く。
   - 条件・並べ替え・市場・業種を変えると、ページは 1 に戻る。
   - 画面は URL から描画する（サーバーコンポーネントが `searchParams` を読み、`screen_stocks` を呼ぶ）。URL をリロード・共有・直接開いても同じ結果になる。
   - URL の値が不正（範囲外、数値でない、未知の列名、未知の市場コード、不正なページ番号など）のときは、**その項目だけ既定値を使い**、結果の上に「URL の条件の一部（cagr）が無効なため、既定値で表示しています」と表示する。描画中に例外を投げない。ページ番号が最終ページを超えるときは最終ページを表示する。
   - **受け付ける値の形（R3）**。画面（サーバーコンポーネント）と `GET /api/screening` は、同じ検証の関数（`src/lib/screening/params.ts`）を使う。違いは不正な値の扱いだけ（画面は既定値に置き換えて注記、API は 400）。
     | 項目 | 有効 | 無効 |
     |---|---|---|
     | 閾値（`cagr`・`margin`・`years`）の文法 | 正規表現 `^-?\d{1,4}(\.\d)?$` に一致し、かつ第2章の2の範囲内。例: `20`、`20.0`、`20.5`、`-5`、`-0`（0 とみなす）、`005`（5 とみなす） | `+20`、`.5`、`20.`、`20.55`、`1e1`、`Infinity`、`NaN`、全角数字（`２０`）、前後の空白（`%2020`、`20%20`）、空（`cagr=`） |
     | 閾値の正規化 | URL に書き直すときは正規形にする: 先頭の余分な 0 を除き、`.0` を除き、`-0` は `0`（例: `020.0` → `20`、`-0` → `0`、`20.5` → `20.5`） | — |
     | `off` | `cagr`・`margin`・`years` のカンマ区切り | それ以外の要素 |
     | `market` | `0111`・`0112`・`0113` のカンマ区切り | それ以外の要素 |
     | `sector` | **33業種の固定の一覧**（J-Quants／東証の33業種コード `0050` 水産・農林業 〜 `9050` サービス業 の33個。アプリにコードと名前の定数として持つ。市場データではない）にあるコードのカンマ区切り。DB に銘柄の無い業種のコードも有効 | 一覧に無いコード（`9999`「その他」を含む） |
     | `unavailable` | `include`、`exclude`（`exclude` は既定と同じ。正規化した URL では省略） | それ以外 |
     | `sort` | `cagr`、`margin`、`years`、`code`、`name`、`market`、`sector` | それ以外 |
     | `order` | `asc`、`desc`（`sort` が無ければ既定の `cagr` に対する向き） | それ以外 |
     | `page` | `^[1-9]\d{0,5}$` | `0`、`-1`、`abc`、`1.5` |
     - **同じパラメータの重複**（`?cagr=10&cagr=20`、`?market=0111&market=0113`）: その項目は無効（画面は既定値＋注記、API は 400）。
     - **カンマ区切りの値の重複**（`market=0111,0111`、`off=cagr,cagr`）: 有効。重複を除く。正規化した URL では重複を除き、`market`・`sector` はコードの昇順、`off` は `cagr,margin,years` の順に並べる。
     - **一部だけ不正**（`off=cagr,foo`、`market=0111,9999`、`market=0111,`（空の要素））: 画面は**正しい要素だけを残し**、注記に項目名を出す（例: `market=0111,9999` → プライムだけを選んだ状態で、「URL の条件の一部（market）が無効なため…」）。API は 400（`fields: ["market"]`）。
     - **カンマ区切りの項目が空**（`market=`、`off=`、`sector=`）: 指定なしと同じ（有効）。
     - **未知のパラメータ**（`?foo=1`）: 画面・API とも無視する（注記も 400 も出さない）。画面で次に操作したときの URL には残さない。
     - **業種のチップ**: 選んだ業種は、固定の一覧の名前でチップに出す。DB に銘柄の無い業種（例: `sector=0050`）は「水産・農林業（該当銘柄なし）」と出し、業種の一覧にもその行を銘柄数 0 で加える（外せるようにするため）。
     - **入力欄に不正な値が残ったまま別の操作をしたとき**（例: CAGR の欄に `abc` を入れてエラーが出ている状態で、条件② をオフにする）: URL の `cagr` には**直前の有効な値**を書き、結果もその値で絞り込む。入力欄の `abc` とエラー表示はそのまま残す（利用者の入力を消さない）。入力欄を有効な値に直すと、その値で更新される。
   - 未ログインで条件付きの URL を開くと、`/login?next=<その URL（クエリを含む）>` に送られ、ログイン後に同じ条件で表示される（Sprint 1 の `next` の仕組み）。
7. **更新のタイミング（AC6.2「すぐ更新」）**
   - 数値入力: 入力が止まって 400 ミリ秒後、または Enter・フォーカスを外したときに URL を書き換える。スライダー: 操作を終えたとき（離したとき・キー操作のたび）に書き換える。スライダーを動かしている間も、数値入力の表示は追従する。
   - スイッチ・チェックボックス・並べ替え・ページ送り: すぐに書き換える。
   - 書き換えから結果の描画まで（ローカル、4,000 銘柄）: 2 秒以内。取り直しの間は、結果の表に「更新中…」を表示し（`aria-busy="true"`）、前の結果を薄く残す。
8. **空状態（AC6.9）**
   - 銘柄マスタが0件: 条件パネルは表示したまま、結果の場所に「まだデータが取り込まれていません」と、取り込み状況画面（`/imports`）へのリンクを表示する（ダッシュボードの空状態と同じ部品・文言の系統）。
   - 銘柄マスタはあるが、該当が0件: 「条件に一致する銘柄はありません」と、条件を緩める手がかり（「閾値を下げる、条件をオフにする、または『算出不可を含める』をオンにすると表示される場合があります」）。
   - 銘柄マスタはあるが、財務指標が1件も無い、または初出日が1件も無い: 結果の上に「財務指標がまだ算出されていません」／「株価の初出日がまだ取り込まれていません」の注意と `/imports` へのリンクを出す（0件の理由がデータ不足であることを伝える）。
   - 読み出しに失敗したとき: 0件として扱わず、「検索結果を読み込めませんでした」のエラー表示（`role="alert"`）にする。
9. **Sprint 5 評価の任意の改善（取り込み状況の画面）**
   - D1: 「銘柄コードで確認」の2枚のカードは、**幅にかかわらず縦に積む**のを正式な設計とする（財務の表が横幅を使うため）。契約の記述をこちらに合わせる。
   - D2: 幅 375px の「算出不可の内訳」の表は、理由の列を折り返し、件数の2列が横スクロール無しで見えるようにする。
   - D3: 要約のタイルで、値が「—」「なし」のときの補足（「財務の取り込み実績がありません」など）は、値の下に小さく出す（「銘柄マスタ 8 銘柄のうち」と同じ形）。
   - 進行中の注意（「『通期実績が5期未満』には取り込み途中の銘柄が含まれます」）は、財務のカードでは CAGR の理由が `insufficient_periods` のときだけ出す（区画の注意はそのまま）。
   - Q1: 取引カレンダーの要求がキーの無効（403）・401・429 で打ち切られたとき、`details.lastFailedStatus` にその HTTP ステータスを記録する。
   - Q2: 期限切れで打ち切ったとき、取得できた開示日が0なら「失敗」にする（ほかの打ち切りの理由とそろえる）。

## 4. 画面とエンドポイント

### ナビゲーション

`NAV_ITEMS` を「ダッシュボード → **スクリーニング**（`/screening`）→ 取り込み状況 → 設定」にする。デスクトップのナビゲーションと 375px のドロワーの両方に出る。`/screening` を開いているときは「スクリーニング」が現在の画面として示される。

### スクリーニング画面 `/screening`（`src/app/(app)/screening/`）

見出し「スクリーニング」と、その下に1行の補足「保存済みデータから検索します（基準日 YYYY-MM-DD。推定上場年数は株価データの初出日からの推定）」。基準日が無ければ「基準日なし（株価の取り込み実績がありません）」。

**レイアウト**
- 幅 1024px 以上: 左に条件パネル（幅 300px 前後、`data-testid="screening-conditions"`）、右に結果。条件パネルはページのスクロールに追従する（sticky）。
- 幅 1024px 未満: 条件パネルは折りたたむ。結果の上に、1行の要約（「CAGR ≥20% ・ 営業利益率 ≥10% ・ 上場5年以内」、オフの条件は「オフ」）と「条件を変更」のボタンを置き、押すと条件パネルが開く（同じ部品。閉じるボタンと Esc で閉じる）。**AC6.12 の注記は、この要約の直下に常に表示する**（パネルを開かなくても見える）。

**条件パネル**（上から）
1. **条件① 売上CAGR**
   - スイッチ（ラベル「条件① 売上CAGR を使う」）、見出し「売上CAGR ≥ [ 20 ] %」（数値入力、`aria-label="売上CAGR の閾値（%）"`）、スライダー。
   - 注記（小さい文字）: 「直近5期の通期実績から算出（成長4年分）」
   - **暫定の注記（AC6.12。`data-testid="cagr-provisional-note"`）**: 「上場から約4年未満の銘柄は、上場前の期のデータがまだ無いため通期実績が5期に満たず、条件①（売上CAGR）を算出できません。」情報のアイコンと、控えめな背景で示す。1280×800 の画面で、スクロールなしに条件①と一緒に見える位置にある。
2. **条件② 営業利益率**: 同じ構成。「営業利益率 ≥ [ 10 ] %」、注記「直近の通期実績の営業利益 ÷ 売上高」。
3. **条件③ 上場年数**: 同じ構成。「上場 [ 5 ] 年以内」、注記「株価データの初出日からの推定。データ期間開始以前から上場している銘柄は満たしません」。
4. **算出不可を含める**: スイッチ（既定オフ）。説明「オンにすると、値を算出できない銘柄（通期実績が5期未満、営業利益の開示なし、財務データなし、初出日が未確定など）も、その条件を除いて判定して表示します。銀行など営業利益を開示しない会社は、営業利益率が算出不可になります。」
5. **市場区分**: 「プライム」「スタンダード」「グロース」のチェックボックス。何も選ばないときは「すべて」（見出しの横に「すべて」と表示）。
6. **業種**: 「業種を選ぶ」のボタンで、33業種のチェックボックスの一覧（DB に保存された銘柄にある業種だけを、33業種コード順に、銘柄数付きで）を開く。選んだ業種は、ボタンの下に名前のチップで並び、チップの × で外せる。何も選ばないときは「すべて」。
7. 「既定の条件に戻す」のボタン（すべてを既定に戻す。URL は `/screening?cagr=20&margin=10&years=5&sort=cagr&order=desc`）。

オフにした条件は、入力欄とスライダーが無効（`disabled`）になり、見た目も薄くなる。閾値の値は保たれ、オンに戻すとその値で絞り込む。

**結果**（`data-testid="screening-results"`）
- 上部（`data-testid="result-summary"`、`aria-live="polite"`）: 「該当 **N** 件（銘柄マスタ M 銘柄中）」。N は3桁区切り。
  - 「算出不可を含める」がオフで、オンにすると増える銘柄があるとき: 「算出不可・未確定のため除外: K 件」と、スイッチをオンにするボタン「含めて表示」。
  - ページの位置「1〜100 件目を表示」。
- 表（`<table>`、見出しは `th`）:
  | 列 | 内容 |
  |---|---|
  | コード | 5桁（`99991`） |
  | 社名 | 社名。長い社名は2行まで折り返し、それを超えたら省略し、`title` で全体 |
  | 市場区分 | `プライム`／`スタンダード`／`グロース` |
  | 業種 | 33業種名 |
  | 売上CAGR（%） | `41.4%`。算出不可は `算出不可（通期実績が5期未満）` など（Sprint 5 の理由の表示）。財務データが無ければ `財務データなし` |
  | 営業利益率（%） | `12.0%`。算出不可は `算出不可（営業利益の開示なし）` など。財務データが無ければ `財務データなし` |
  | 推定上場年数（初出日） | `3.0年` と、その下に小さく `2023-09-24`。データ期間開始以前は `9年超` と小さく `データ期間開始以前`。初出日が無ければ `未確定`。基準日が無ければ `—` |
  | 条件 | ①②③の3つの小さな印を並べる（第2章の3の状態。`data-testid="condition-status-cagr"` などに `data-status="met|unmet|unavailable|off"`） |
  - 各行は `data-code="99991"` を持つ。行はリンクにしない（銘柄詳細は Sprint 7）。
  - 数値の列は右揃え、`tabular-nums`。％は小数点以下1桁、年数は小数点以下1桁、日付は `YYYY-MM-DD`。
  - 値のセルと条件の印の見た目:
    - 満たす: 控えめなアクセントカラーの文字と ✓ のアイコン
    - 満たさない: グレーの文字（値そのものは読める濃さ）と、印は「−」のアイコン
    - 算出不可・財務データなし・未確定: 斜体またはグレーの小さい文字で「算出不可（…）」と、印は「?」のアイコン。数値と見た目で区別できる
    - オフ: 印は薄い「オフ」の表示。値のセルは通常の文字（色付けしない）
    - 色だけに頼らず、アイコンと文字でも区別する。印には `title`（例: 「条件① 売上CAGR ≥20%: 満たす」）とスクリーンリーダー用の文字を付ける。
  - 列見出し: 売上CAGR・営業利益率の見出しに現在の閾値の補足は付けない（条件パネルにあるため）。推定上場年数の見出しの補足に「初出日から推定」。
- 下部: ページ送り（「前へ」「次へ」と「2 / 3 ページ」）。1ページは100件。全体が100件以下なら出さない。
- 幅 1024px 未満では、表は結果の枠の中だけで横スクロールし、コードと社名の列を左に固定する。ページ全体の横スクロールは無い。

### C11. 性能（m4。`pnpm test:db` の中で合否を判定する）
1. 生成したコード（`8Z000`〜`8Z999`・`7Z000`〜… のような、実在しない形で、後片付けで一括して消せるもの）で、銘柄 4,000 件、初出日 4,000 件、各5期の通期実績（トリガーで `financial_metrics` 4,000 行）を投入する。一部は算出不可、一部はデータ期間開始以前、一部は初出日なしにする。基準日のための `ingestion_runs` の行も作る。
2. **測定のロール**: `screen_stocks` は security invoker なので、`postgres` ではなく、**許可リストに登録された authenticated ユーザーとして**測る。テストでは、1つのトランザクションの中で `set local role authenticated` と `set local request.jwt.claims = '{"sub":"<許可ユーザーの id>","role":"authenticated"}'` を設定して呼ぶ（`current_user_is_allowed()` が `auth.uid()` から `auth.users` を引くため、`seed:users` の owner の id を使う）。RLS が効いていることを、同じ設定で `select count(*) from public.stocks` が 4,000 以上になり、`sub` を許可リスト外のユーザー（intruder）にすると 0 になることで確かめる。
3. **合否の基準**: 次の各場合で、`screen_stocks` の1回の実行時間（テストのクライアントから見た往復時間）を、**最初の1回をウォームアップとして除いた5回の中央値**で測り、**100 ミリ秒を超えたらテストを失敗させる**。評価者は `pnpm test:db` の結果で判定する（このテストが失敗すれば C11 は不合格）。
   - 既定の条件
   - 3条件オフ・算出不可を含める（4,000 件が対象）で、並べ替えが売上CAGR・営業利益率・推定上場年数・社名のそれぞれ
   - 市場・業種の絞り込みあり
   - 最終ページ
4. **行ごとの年数の計算が無いこと**: 1回の `screen_stocks`（3条件オフ・4,000件・推定上場年数で並べ替え）で、`listing_years_between` の呼び出しが**ページの行数（100）以下**であることを確かめる。
   - `listing_years_between` が plpgsql（現状）のまま: `postgres` のセッションで `set track_functions = 'all'` にし、1つのトランザクションの中で（2のロールの設定の後に）`screen_stocks` を呼び、同じトランザクションの中で `select pg_stat_get_xact_function_calls('public.listing_years_between(date,date)'::regprocedure)` を読む（トランザクション内の値なので、統計の反映の遅れを受けない）。累積の `pg_stat_user_functions` で見る場合は、呼び出したトランザクションをコミットした後に `select pg_stat_force_next_flush()` を呼び、別のトランザクションで `select pg_stat_clear_snapshot()` の後に読んで、前後の差を取る。
   - `listing_years_between` を SQL 関数に書き換えてインライン化した場合（上の方法では数えられない）: `screen_stocks` の中の年数を求める部分と同じ問い合わせを `explain (analyze, verbose)` で実行し、年数の計算を含むノードの `actual rows × loops` がページの行数以下であることを確かめる。
