## 契約の範囲外の変更の妥当性
- **`/API/...` を大文字小文字に関係なく 401 にした変更**: 妥当。
  - 未ログインで `/API/...` を開いたとき、以前はログイン画面へのリダイレクト（307）になっていた。これを、JSON の 401 にそろえている。
  - C7-11 の `/API/cron/daily` の条件とも合っている。
  - `/API/ingestion` なども 401 で、保護は弱まっていない。
- **N1 の修正方法**（Cookie があって `reason=revoked` のときは、未ログインでも理由を付ける）: 妥当。
  - ログイン画面は、もともとクエリの `?reason=revoked` だけでメッセージを出す。そのため、攻撃に使える範囲は広がっていない。
  - 許可されたユーザーがこの URL を開いても、セッションは破棄されないことを確認した。
  - 期限切れの Cookie を持つ人が外部のリンクから開くと、「取り消し」の文言が出るという小さな誤表示はありうる。ただし実害は無い。
- **データソースのカードの「最終成功」**: 妥当。
  - 実行履歴から集計した実際の値である。DB に投入した株価の成功の行が、J-Quants のカードに反映されることを確認した。
  - ダミーではない。
- **Sprint 2 の E2E 1件の変更**（`dashboard.spec.ts`）:
  - 変更前は「取り込み状況の画面に、取り込みのボタンが無い」ことを確かめていた。これは、Sprint 2 の時点で未実装の機能を出さないための確認だった。
  - 変更後は「今すぐ取り込み」が見えることを確かめる。
  - Sprint 3 で機能が加わったことに合わせた更新で、確認を緩めてはいない（ダミーや「準備中」の表示が無いことの確認は残っている）。妥当と判断する。

## 改善提案（合格判定には影響しないが推奨）

### M1（Minor）: 正規でないホスト名で開くと、手動取り込みが 403 になり、「ログインし直してください」と誤った案内が出る
- 再現: `http://127.0.0.1:3100` で開いて POST する（`Origin: http://127.0.0.1:3100`、`Host: 127.0.0.1:3100`）と、403 `forbidden` になる。画面の文言は「取り込みを開始できませんでした。ログインし直してください」。
- 原因: `request.nextUrl.origin` が、`Host` ヘッダーではなく、サーバーの既定のホスト名（localhost）から作られる。ログアウト（Sprint 1）も同じ判定である。
- 影響: ローカル以外では起きにくい。Vercel では、独自ドメインと `*.vercel.app` の両方で開ける場合がある。本番で、`nextUrl.origin` と `Origin` が一致することを確かめておきたい。
- 提案:
  - Origin が不一致のとき（403）の文言を、「ログインし直してください」とは分ける。
  - 許可するオリジンを、`Host` ヘッダーや、環境変数に設定した正規の URL と比べる。

### M2（Minor）: 正しいシークレット付きの `HEAD /api/cron/daily` でも、取り込みが実行される
- Next.js の Route Handler は、HEAD を GET として処理する。そのため、HEAD でも実行履歴が1行増える（評価中に1件確認した）。
- シークレットが必要なので、安全上の問題は無い。ただ、死活監視などで HEAD を送ると、取り込みが走る。
- 提案: `HEAD` を明示的に定義して 405 にする。

### M3（Minor）: 対象外の行に1件でも形式の違いがあると、取り込み全体が失敗する
- `masterItemSchema` は、保存しない行（ETF、TOKYO PRO MARKET など）にも、`S33Nm`、`MktNm`、`Date` の形式などの必須の条件をかけている。
- 契約の C9-2 どおりではある。ただ、実データで、保存しない行の項目が1つ空になっているだけでも、毎日の取り込みが止まる。
- 提案: 保存しない行については、判定に使う `ProdCat`、`Mkt`、`S33`、`Code` だけを必須にする。

### M4（Minor）: ボタンを押した直後にリロードすると、結果の文言が表示されない
- 自己評価の既知の問題のとおり。結果は実行履歴の表で確認できる。

### M5（Minor）: C4-2（接続できない）を、実際の環境では確認していない
- 単体テストだけで確認している。
- 提案: E2E で、`JQUANTS_API_KEY` を設定したうえで、到達できない J-Quants の URL を環境変数で差し替えられるようにする。そうすれば、画面まで通しで確認できる。
