# Sprint 07 契約: F7 銘柄詳細画面

## 1. 対象機能

F7 銘柄詳細画面。1銘柄の保存済みデータ（銘柄マスタ、株価の初出日、通期実績、財務指標）を1画面にまとめる。
- 基本情報（コード、社名、市場区分、業種）
- 通期5期分（FY-4〜FY0）の売上高・営業利益のグラフと表。足りない期は「データなし」
- 売上CAGR・営業利益率・推定上場年数と、算出に使った期（または算出不可の理由）
- 現在の閾値（スクリーニング画面の条件）に対する条件①〜③の判定と、スクリーニング結果に含まれるかどうか

新しい画面 `/stocks/[code]` と `GET /api/stocks/[code]` を加える。スクリーニング結果の行を詳細へのリンクにし（Sprint 6 では行をリンクにしていなかった）、詳細から戻ると直前の条件と並べ替えが保たれる。

大株主・役員（Sprint 8）、各期の EDINET の出典（Sprint 9）、条件④と保有状態（Sprint 10）は、この画面に後から区画を足す。今回は作らない（第8章）。

### 仕様書の受け入れ基準（引用）

- AC7.1 スクリーニング結果の行をクリックすると、その銘柄の詳細画面に移動する。URL を直接開いても表示される（ログインが必要）。
- AC7.2 通期5期分（FY-4〜FY0）の売上高と営業利益が表とグラフで表示され、値はデータベースに保存された値と一致する。保存済みの通期実績が5期に満たない場合は、ある分だけが表示され、足りない期は「データなし」と示される。
- AC7.3 売上CAGR、営業利益率、推定上場年数が、算出に使った期（例: 「2021/03期 → 2025/03期（4年）」）と一緒に表示される。算出不可の場合は理由が表示される。
- AC7.4 現在の閾値に対して各条件を満たすかどうかが、条件ごとに表示される。
- AC7.5 存在しない銘柄コードの URL を開くと「銘柄が見つかりません」と表示される。
- AC7.6 スクリーニング画面に戻ると、直前の条件と並べ替えが保たれている。

関連する仕様の記述（改訂2・デザインの方向性）:
- 「財務値の出典（決算短信／有価証券報告書／有価証券届出書）は、詳細の表では期ごとに小さなラベルで示す」。今回の出典は決算短信だけなので、全期が「決算短信」になる（Sprint 9 で EDINET の出典が加わる）。
- 「金額は百万円または億円単位で表示し、単位を明記する」。日付は YYYY-MM-DD。

### 持ち越し事項とユーザーの決定の扱い

- **金融業は特別扱いしない（ユーザーの決定）**: 詳細画面でも業種による分岐をしない。銀行（`99997`）は営業利益が各期「開示なし」、営業利益率は「算出不可（営業利益の開示なし）」、条件②は「算出不可」と表示される。それ以外の銘柄と同じ部品・同じ規則で表示する。
- **Sprint 6 評価の軽微な指摘（m1〜m5）と CLAUDE.md の後片付けの説明**: 第2章の9と C12 のとおり実施する。任意の項目なので、未実施のものがあれば self-review に明記し、合否には含めない（実施したものは C12 で確かめる）。
- **AC6.12 の暫定の注記**: 詳細画面でも、売上CAGR が「算出不可（通期実績が5期未満）」の銘柄では、CAGR の横に同じ文言（`PROVISIONAL_CAGR_NOTE`）を出す。文言は1か所の定数を共有し、Sprint 9（AC15.12）で両方の画面の注記を一度に差し替えられるようにする。

## 2. 仕様上の論点と、このスプリントでの解釈

評価者は、この解釈が妥当かも判断してほしい。

1. **「現在の閾値」（AC7.4）はスクリーニングの URL の条件**
   - スクリーニングの状態はすべて URL にある（Sprint 6）。スクリーニング結果の行のリンクは、そのときの条件のクエリ（`serializeScreeningParams` の正規形。`cagr`・`margin`・`years`・`off`・`unavailable`・`market`・`sector`・`sort`・`order`・`page`）をそのまま付けた `/stocks/99991?cagr=15&margin=10&years=5&sort=cagr&order=desc` にする。
   - 詳細画面は、このクエリを Sprint 6 と同じ検証の関数（`src/lib/screening/params.ts` の `parseScreeningParams`）で読み、条件①〜③を判定する。
   - クエリが無い（URL を直接開いた、取り込み状況の画面から開いた）ときは既定の条件（20・10・5、すべてオン、算出不可を含めない）で判定し、「既定の条件で判定しています」と示す。
   - クエリの一部が不正なときは、Sprint 6 の画面と同じく**その項目だけ既定値**にして「URL の条件の一部（cagr）が無効なため、既定値で判定しています」と出す。描画中に例外を投げない。
   - 詳細画面では閾値を変えない（変える操作はスクリーニング画面に集める）。「条件を変える」はスクリーニングに戻るリンクにする。
   - リンクに付けるのは、表示している結果の条件（サーバーが判定に使った条件）。入力欄で確定前の値があっても、それはリンクに入らない（表示中の印・件数と詳細の判定を一致させるため）。
2. **判定は1か所（スクリーニングとの一致）**
   - 条件ごとの状態（`met`／`unmet`／`unavailable`／`off`）の定義は Sprint 6（契約の第2章の3）と同じ。データ期間開始以前は条件③で `unmet`。
   - 判定は `screen_stocks` と**同じ SQL の式**で行う。二重に実装しない。方法は、`screen_stocks` の候補の絞り込みに銘柄コードの指定を加えて「除外せずに評価だけ返す」使い方を足すか、判定の式を共通の SQL 関数に切り出す（どちらでもよい。Sprint 6 の性能テスト（100ms）は引き続き通ること）。
   - 詳細画面には、3条件の判定に加えて、**そのスクリーニングの条件で結果に含まれるかどうか**を1行で示す。含まれるかどうかは、同じ条件の `screen_stocks` の全件の結果にそのコードがあるかと一致させる（市場区分・業種の絞り込みも含めて判定する）。
     | 状態 | 表示 | 優先順位 |
     |---|---|---|
     | 含まれる | 「現在の条件でスクリーニング結果に含まれます」 | — |
     | 市場区分・業種の絞り込みの外 | 「市場区分・業種の絞り込みの対象外のため、スクリーニング結果に含まれません」 | 1 |
     | オンの条件に `unmet` がある | 「条件②を満たさないため、スクリーニング結果に含まれません」（該当する条件をすべて並べる。例「条件①・条件③を…」） | 2 |
     | オンの条件に `unavailable` があり、算出不可を含めない | 「条件①が算出不可のため、スクリーニング結果から除外されています（『算出不可を含める』をオンにすると表示されます）」 | 3 |
   - 一致は `pnpm test:db` で網羅的に確かめる（C10）。
3. **5期の枠（FY-4〜FY0）の決め方（AC7.2）**
   - FY0 は保存済みの通期実績（`financial_periods`）のうち、事業年度の終了日が最も新しい期。
   - FY-1〜FY-4 は、1つ新しい枠の期の**開始日の前日**に終わる期（Sprint 5 の「連続」の定義と同じ。DB の `financial_metrics_from_periods` の判定と一致する）。
   - 1つ新しい枠が「データなし」のときは、その枠の想定の終了日 E から、次の枠の想定の終了日を次の規則で決める（R2）。
     - **E が月末なら、前年の同じ月の末日**（例: 2025-02-28 → 2024-02-29、2024-02-29 → 2023-02-28、2025-03-31 → 2024-03-31）。
     - **E が月末でなければ、前年の同じ月の同じ日**（例: 20日締めの 2024-08-20 → 2023-08-20。月末でない日は前年の同じ月に必ずあるので、日付のずれは起きない）。
     - 探すのはその終了日に**ちょうど**終わる期（開始日は問わない。見つかった期が変則決算なら印を付ける）。
   - 例: FY-2 が 2022-04-01〜2023-03-31 で、2022-03-31 に終わる期が無ければ FY-3 は「2022/03期 データなし」、FY-4 は 2021-03-31 に終わる期があればそれを表示する。
   - 例（2月決算・うるう年）: FY0 が 2025-03-01〜2026-02-28 で、FY-1（2025-02-28 に終わる期）が無ければ FY-1 は「2025/02期 データなし」。FY-2 の想定の終了日は 2024-02-29 で、2024-02-29 に終わる期があれば FY-2 に入る。
   - 「データなし」の枠にも決算期（例「2022/03期」）を示す（どの期が足りないかが分かるように。AC15.5 の準備）。期間の列は「—」。
   - 5期の枠に入らない保存済みの期（6期以上前の期、連続しない期）は、表の下の「保存済みの通期実績をすべて表示（N期）」を開くと見られる（データを隠さない）。枠に入った期には、その一覧でも位置（FY0 など）を示す。
   - 売上CAGR の算出に使った期（CAGR が算出できたときの FY-4〜FY0）は、DB の `revenue_cagr_base_fiscal_year_end`〜`latest_fiscal_year_end` と一致する。表では、算出に使った枠に印（例: 行の左端の細い線と「算出に使用」の補足）を付ける。CAGR が算出不可のときは付けない。
   - 変則決算の期には、Sprint 5 と同じ「変則決算（9か月）」の印を付ける。同じ期に複数の開示がある期（`disclosure_count` > 1）には「開示2件（訂正あり）」を付け、`title` に「元の開示と訂正を合わせて2件。最新の開示の値を表示しています」と補う。取り込み状況の画面の財務のカードの「訂正あり（N件）」も同じ表記にそろえる（件数は元の開示を含むため）。
4. **表示する値と単位**
   - 金額は**百万円**（`formatMillionYen`。四捨五入、3桁区切り）。表の見出しとグラフの軸に「百万円」を明記する。セルの `title` に円の値（例「40,000,000,000円」）を入れ、保存値と照合できるようにする。
   - 値が NULL の項目は「開示なし」（Sprint 5 と同じ）。期そのものが無い枠は「データなし」。両者を見た目でも区別する。
   - 売上CAGR・営業利益率は DB の `*_display_pct`（切り捨て済み）、推定上場年数は DB の `listing_years_between` の値を表示するだけで、アプリ側で計算しない（Sprint 4・5・6 と同じ）。
   - 営業利益率の補足は「2025/03期: 営業利益 4,800 ÷ 売上高 40,000（百万円）」。表示するのは FY0 の保存値（DB が算出に使った値）で、割り算の結果はアプリで計算しない。
   - 推定上場年数の補足は「初出日 2022-09-24 → 基準日 2026-09-24（株価データの初出日からの推定）」。データ期間開始以前は「データ期間開始以前から上場（9年超）」と「データ期間の開始日 2016-09-26。これより前の上場日は分かりません」。初出日が無ければ「未確定（株価の初出日が未取り込み）」。基準日が無ければ「基準日なし（株価の取り込み実績がありません）」。
5. **グラフ**
   - 5期の枠ごとに、売上高と営業利益の2本の縦棒（グループ化した棒グラフ）。縦軸は百万円。0 の線を引き、営業損失（負の値）は 0 の線より下に描く。
   - 「データなし」の枠は棒を描かず、枠の位置に「データなし」と表示する。「開示なし」の項目は、その棒だけを描かず「開示なし」と表示する。
   - 色は `globals.css` のトークン（ライト・ダークの両方）。系列は色だけでなく凡例と並び順（売上高が左）で区別する。
   - ホバー（またはフォーカス）で、期・系列・値（百万円）を表示する。グラフ全体に `role="img"` と、内容を要約した `aria-label` を付ける。数値の読み取りは表で行える（表が代替になる）。
   - 実装方法（手書きの SVG か、ライブラリか）はジェネレーターが決める。外部 CDN から読み込まない。サーバーで描画でき、JavaScript が無くても棒が表示されること（ホバーの表示だけはクライアント）。
   - テスト用に、棒の要素に `data-slot="FY0"`・`data-series="net_sales|operating_profit"`・`data-value="<百万円の表示値>"` を付ける。
6. **URL と銘柄コード**
   - `/stocks/[code]`。コードは `normalizeStockCode`（Sprint 4）で正規化する。
     - 正規形と違う（小文字 `9y001`、4文字 `7203`）ときは、正規形の URL（`/stocks/9Y001`、`/stocks/72030`）にリダイレクトする。クエリは保つ。
     - コードの形でない（`abc-1`、6文字以上など）、または銘柄マスタに無いコードは「銘柄が見つかりません」（HTTP 404）。
   - `/stocks`（コードなし）と `/stocks/99991/zzz` は、既存のアプリ全体の 404（global-not-found）。
7. **「銘柄が見つかりません」（AC7.5）**
   - `src/app/(app)/stocks/[code]/not-found.tsx` を置き、ページで `notFound()` を呼ぶ。保護画面の枠（ヘッダー・ナビゲーション・フッター）の中に、「銘柄が見つかりません」、開いたコード（正規化できたときだけ）、「銘柄マスタに無いコードか、上場廃止などで一覧から外れた可能性があります」、スクリーニングに戻るリンク（クエリがあれば保つ）を表示する。HTTP ステータスは 404。
   - 未ログインのときは、銘柄の有無を明かさず `/login?next=` へ送る（先に認証）。
   - 描画中に `notFound()`／`redirect()` を投げるので、`simulateServerClockBehind()`（CLAUDE.md の dev の既知の落とし穴）の状態でもコンソールのエラーと `pageerror` が0件であることを確かめる（C6）。
8. **スクリーニングとの行き来（AC7.1・AC7.6）**
   - スクリーニング結果の各行: コードと社名のセルを `<a>`（next/link）にする。行のほかの部分をクリックしても同じ詳細に移る（行全体をクリックできる。テキストの選択中・修飾キー付きのクリックは邪魔しない）。キーボードではリンクに Tab で移り Enter で開ける。行のホバーで、クリックできることが分かる見た目にする。新しいタブで開く（中クリック・⌘クリック）ことができる。
   - 詳細画面の上部にパンくず「スクリーニング › 99991 検証用成長二五株式会社」を置き、「スクリーニング」は `/screening?<受け取ったクエリ>`（クエリが無ければ `/screening`）へのリンクにする。
   - ブラウザの「戻る」でも、スクリーニングの直前の URL（条件・並べ替え・ページ）に戻る（Sprint 6 は条件の変更を `router.replace` で書くので、履歴の直前はそのときの URL）。
   - ナビゲーションでは、詳細画面を開いているときにどの項目も `aria-current="page"` にしない（詳細はナビゲーションの画面ではない）。パンくずで位置を示す。
   - **ヘッダーのナビゲーションの「スクリーニング」からの戻り（R3。案 (a) を採る）**: 詳細画面（「銘柄が見つかりません」を含む）を開いている間だけ、ナビゲーションの「スクリーニング」のリンク（デスクトップと 375px のドロワーの両方）の `href` を、パンくずと同じ `/screening?<受け取ったクエリ>` にする。クエリはスクリーニングの条件のパラメータだけを、正規形で付ける（未知のパラメータは付けない。受け取ったクエリに不正な項目があれば、パンくずと同じく不正な項目を除いた正規形）。クエリが無ければ `/screening`。ほかの画面では、ナビゲーションの「スクリーニング」は従来どおり `/screening`。これで、パンくず・「条件を変える」・ナビゲーション・ブラウザの「戻る」のどれで戻っても、直前の条件と並べ替えが保たれる（AC7.6）。
   - **行全体のクリック**: JavaScript で行のクリックを遷移にする場合、行の中のリンク（コード・社名）をクリックしたときは二重に遷移しない（履歴が1件だけ増える）。中クリック（`auxclick`）と ⌘／Ctrl クリックは、行のどこでも新しいタブで開く（元のタブは移らない）。
   - 取り込み状況の画面の「銘柄コードで確認」の結果（銘柄マスタにあるコード）に、「銘柄詳細を開く」のリンク（`/stocks/<code>`）を加える。
9. **Sprint 6 評価の軽微な指摘（任意。実施したものは C12 で確かめる）**
   - m1: 「既定の条件に戻す」で、すべての入力欄を既定値にし、入力のエラー表示を消す（確定済みの値が既定と同じでも）。
   - m2: 1280px で、算出不可の文言と「データ期間開始以前」が1〜2文字だけ次の行に落ちないようにする（列の幅・`text-balance`・短い表記と `title` など）。
   - m3: 右揃えの列の並べ替えの矢印を、見出しの文字の隣に置く。
   - m4: 1280×800 で、条件パネルの市場区分・業種の絞り込みがパネルの中のスクロールに隠れて気づけない問題を直す（説明の短縮・配置の見直し・下端のフェードなど）。直した結果、1280×800 で「市場区分」の見出しがスクロールなしで見えること。AC6.12 の注記が条件①と一緒に見えること（C1-5）は保つ。
   - m5: 条件の印の `title` とスクリーンリーダー用の文字は、結果の条件（サーバーが判定に使った閾値）から作る。
   - CLAUDE.md: `pnpm test:db` の後片付けの説明を、実際の接頭辞（`9999x`・`9Z…`・`P…`・`0000Z〜3999Z`、今回の `9Y…`）に合わせる。
   - （任意の改善提案）`listing_first_date_cutoff` の `p_max_years` を関数の側でもアプリの閾値の上限（`params.ts` の `THRESHOLDS.years.max`。現在は 100）で丸め、大きな値でエラーにならないようにする。

## 3. 起動方法

ポート 3000 は別のプロジェクトが使っているので、すべて **3100 番**で行う（3000 番のプロセスには触れない。3100 番のサーバーを止めるときは `lsof -ti tcp:3100` で得た PID だけを止める）。

```bash
cd /Users/shuriokamoto/dev/quantis-light
pnpm install
pnpm db:start          # Docker が必要
pnpm db:reset          # Sprint 7 のマイグレーションを含めて適用
pnpm env:local
pnpm seed:users        # owner@quantis.local / Quantis-Owner-2026!
# キーなし（リポジトリ直下の .env に有効な JQUANTS_API_KEY があるため、空の値で上書きする）
JQUANTS_API_KEY= EDINET_API_KEY= CRON_SECRET=local-cron-secret-0123456789 pnpm dev -p 3100
# 本番相当: pnpm build && JQUANTS_API_KEY= EDINET_API_KEY= CRON_SECRET=local-cron-secret-0123456789 pnpm start -p 3100
```

- アプリ: http://localhost:3100/screening → 行をクリック、または http://localhost:3100/stocks/99991
- Postgres: `postgresql://postgres:postgres@127.0.0.1:54322/postgres`
- 評価用ユーザー: `owner@quantis.local` / `Quantis-Owner-2026!`
- E2E: `E2E_PORT=3100 pnpm test:e2e`、DB 込みのテスト: `pnpm test:db`
- 追加する環境変数は無い。

## 4. 画面とエンドポイント

### 銘柄詳細画面 `/stocks/[code]`（`src/app/(app)/stocks/[code]/`）

上から次の順に置く。幅 1024px 以上では、指標と判定の区画を2列（左: 条件の判定、右: 指標）にしてよい。幅 375px では1列に積む。

2. **見出し**（`data-testid="stock-header"`）: コード（等幅）と社名（`h1`）、市場区分と業種の小さなラベル。補足の1行「保存済みデータ（基準日 2026-09-24）」。文書のタイトルは「99991 検証用成長二五株式会社 | Quantis Light」。

   - 「条件を変える」: スクリーニングに戻るリンク（パンくずと同じ URL）。
4. **指標**（`data-testid="stock-metrics"`）: 3つのカード。

   - 営業利益率（`data-testid="metric-margin"`）: 値（`12.0%`）と「2025/03期: 営業利益 4,800 ÷ 売上高 40,000（百万円）」。算出不可なら理由。
   - 推定上場年数（`data-testid="metric-years"`）: 第2章の4の表示。
5. **業績推移（通期）**（`data-testid="stock-financials"`、見出し「業績推移（通期・直近5期）」、単位「百万円」）
   - グラフ（`data-testid="financial-chart"`）。
   - 5期の表（`data-testid="five-period-table"`、行は `data-slot="FY-4"`〜`"FY0"`、「データなし」の行は `data-missing="true"`）。列: 位置、決算期、期間、売上高（百万円）、営業利益（百万円）、基準（「連結・日本基準」）、出典（「決算短信」の小さなラベル）、開示日（訂正ありの印）。古い期（FY-4）が上。

### C1. スクリーニングから詳細へ（AC7.1）
1. `/screening`（既定の条件）の結果は `9Y001`、`99991`、`99990` の順の3行。`99991` の行の社名のセルをクリックすると `/stocks/99991?cagr=20&margin=10&years=5&sort=cagr&order=desc` に移り、詳細画面が表示される。
