## ジェネレーターの申告の確認

### C4-6 の `years=99`（契約レビュー R1 の誤り）: 申告は正しい
`src/lib/screening/params.ts` の `THRESHOLDS` は、コメントのとおり「値×10 の整数」で範囲を持つ。`normalizeThreshold` は `tenths = int*10 + fraction` と比べる。したがって `years` の範囲は 0.1〜10.0 年で、`years=99`（990）は範囲外で無効になる。1回目の契約レビューの R1 で「1〜100 なので 99 は有効」と書いたのは、評価者が単位を読み違えたためで、誤りだった。改訂2の訂正（`years=99` も無効）を正として判定した。実測の結果も次のとおり:
- `/stocks/99991?cagr=abc&years=99` は 200 で、「URL の条件の一部（cagr, years）が無効なため、既定値で判定しています」と出る。
- `GET /api/stocks/99991?years=99` は 400 `{"error":"invalid_params","fields":["years"]}` を返す。

### 既存の E2E の変更: 検査は弱まっていない
- `financials.spec.ts`: `toContainText("訂正あり（2件）")` を、`corrected-badge` の文言「開示2件（訂正あり）」と、`title` の完全一致の2つの確認に置き換えた。訂正後の値（`14,641`）の確認はそのまま残っている。検査は強くなっている。
- `auth.spec.ts`: `/stocks/72030` は「銘柄が見つかりません」になった（アプリのレイアウトの中の 404。ログイン後の next とフッターの確認はそのまま）。ログアウト後の「戻る」の検査も、同じ URL で残っている。
- `shell.spec.ts`: アプリ全体の 404 の時計のずれの例を `/stocks/72030/zzz` に替えた。「銘柄が見つかりません」を時計のずれの下で確かめる検査は、`stock-detail.spec.ts` の C6 にある。評価者も自分のスクリプトで、時計のずれの下で確かめた（下記の C6）。

### screen_stocks を screening_evaluate 経由にした影響: リグレッションなし
- `screening.db.test.ts`（性能の 100ms を含む）と、screening の E2E（dev・prod）は成功した。
- 詳細の判定とスクリーニングの結果が一致するかも確かめた。ランダムに作った 60 通りの条件（閾値・オフ・算出不可を含める・市場・業種）で、14銘柄 × 60 = 840 件を比べた。比べたのは、`GET /api/stocks/<code>` の `included`・`status` と、`GET /api/screening` に行があるかどうか・行の `status` で、不一致は0件だった。

## バグ（修正必須）

### B1: 閾値を入力した直後に結果の行をクリックすると、詳細に移らずクリックが失われる
- 重要度: Minor（完了条件の手順では再現しないため判定は変えないが、次のラウンドかスプリントで直すこと）
- 再現手順（dev・prod とも毎回再現）:
  1. データを投入し、`/screening?cagr=15&margin=10&years=5&sort=cagr&order=desc` を開く。
  2. 売上CAGR の入力欄に `14` と入力する。
  3. 400ms 以内に、`99992` の行の社名のリンク（または業種のセル）をクリックする。
- 期待結果: 詳細（`/stocks/99992?…`）に移る。契約の第2章の1には「入力欄で確定前の値があっても、リンクには入らない」とあり、クリックしたら遷移すること自体は前提になっている。
- 実際の結果: URL は `/screening?cagr=14&…` になり、詳細には移らない。画面にも変化が無い。メインフレームの遷移の記録にも、`/stocks/…` が一度も現れない。600ms 待ってからクリックすると、正しく移る。
- 根拠と原因の推定: `screening-view.tsx` の、遅延させた `router.replace('/screening?…')` がある。クリックでフォーカスが外れ、入力が確定する（遅延 0 または残りの待ち時間）。その結果、行のクリックで始まった `router.push('/stocks/…')` の後に replace が走り、遷移を上書きしている。詳細への遷移を始めるとき（行の `onClick`・リンクのクリック）に待っている書き換えを取り消すか、先に確定させてからその条件で遷移する必要がある。

## 改善提案（合格判定には影響しない）
- m1: 375px では、グラフの FY0 の棒にマウスを乗せたときのツールチップ（「FY0 2025/03期 営業利益 -1,428」）が画面の右端で切れる。端の枠では左に寄せてほしい。
- m2: 375px の条件の判定で、条件名が「条件① 売 / 上CAGR」のように語の途中で折り返す。「保存済みの通期実績をすべて表示（ 6 期）」は、括弧の内側に余分な空白が入って見える（1280px でも同じ）。
- m3: 99997 の営業利益率の補足が「2025/03期: 営業利益 開示なし ÷ 売上高 24,414（百万円）」になっている。算出不可の理由がすでに見出しにあるので、割り算の形は出さないほうが自然。
- m4: スクリーニングの 1280px で、売上CAGR などの列が広がったため、社名の列が狭くなった。多くの社名が2行に折り返し、「検証用初出日未確定株式…」は省略される。省略した行には `title` で全体を示すか、列の幅の配分を見直してほしい。m4（市場区分を上に移した）の結果、1280×800 では条件③が最初の画面の下端（y≈788）にかかっている。
- 表の負の営業利益は赤の文字だが、グラフの負の棒は同じ色のままになっている。0 の線の下にあるので読めるが、表と合わせるかどうかは検討してよい。
