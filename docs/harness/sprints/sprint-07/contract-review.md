## 修正必須

### R1: C4-6 の `years=99` は不正な値ではない（期待値の誤り）
- `src/lib/screening/params.ts` の `THRESHOLDS.years` は `min: 1, max: 100` です。そのため `years=99` は有効な値として扱われ、「URL の条件の一部（cagr, years）が無効なため…」は出ません。書かれたとおりに実装して検証すると、C4-6 は不合格になるか、Sprint 6 の範囲を黙って変えることになります。
- 修正案: 範囲外の `years=0`・`years=101`、または文法違反の `years=4.95` に差し替えてください。C8-4 の API の `fields` の例も、同じ組み合わせ（例: `?cagr=abc&years=0` → `fields: ["cagr","years"]`）を1つ加えると、画面と API の扱いの違い（既定値で置き換える／400）がそろって確かめられます。

### R2: 「データなし」の枠の想定の終了日が、月末決算（うるう年）で実在の期を取りこぼす
- 第2章の3の規則は「想定の期間（終了日の1年前の翌日〜終了日）の開始日の前日を、次の枠の終了日とする」です。つまり、次の枠の終了日は「終了日の1年前」になります。この規則だと、2月決算で次のようなずれが起きます。
  - 例: FY0 = 2025-03-01〜2026-02-28 で、FY-1（2025-02-28 終了）が無い。FY-1 の想定の終了日は 2025-02-28 で、FY-2 の想定の終了日は 2024-02-28 になる。しかし、実在する期は 2024-02-29 に終わっている。そのため、この期は FY-2 に入らず「データなし」になり、「すべて表示」にしか出なくなる（AC7.2 の「ある分だけが表示され」に反する）。
- C10-3 には「2月末決算（うるう年）の想定の終了日」のテストが挙がっていますが、期待する結果が書かれていません。
- 修正案: 規則を明記してください。例: 「終了日が月末なら、想定の終了日は前年の同じ月の末日にする（2025-02-28 → 2024-02-29）」。月末以外の締め日（20日など）の扱いも書いてください。そのうえで、C10-3 に上の例の期待値（FY-2 = 2024-02-29 の期が入り、`missing: false`）を加えてください。E2E の投入例に入れる必要はありません（単体テストで十分です）。

### R3: AC7.6 で、ヘッダーのナビゲーションの「スクリーニング」から戻ったときの振る舞いが書かれていない
- 契約で「戻る」経路として挙がっているのは、パンくず、「条件を変える」、ブラウザの「戻る」だけです。一方、詳細画面のヘッダーには、ナビゲーションの「スクリーニング」（`/screening`、クエリなし）が常にあります。初めて使う人はこれで戻ることが多く、押すと条件と並べ替えが既定に戻ります。AC7.6 の「スクリーニング画面に戻ると、直前の条件と並べ替えが保たれている」を文字どおりに読むと、評価ではこの経路も確かめることになります。
- 修正案: どちらかに決め、完了条件に書いてください。
  - (a) ナビゲーションから戻っても条件を保つ（例: 詳細画面を開いている間だけ、ナビゲーションの「スクリーニング」のリンクに受け取ったクエリを付ける。または、最後に表示したスクリーニングの URL を覚えておく）。C7 にこの経路を加える。
  - (b) ナビゲーションの「スクリーニング」は、意図して「新しく検索を始める」導線として既定の条件に戻す。その理由と、パンくずで条件を保てることが画面から分かることを、第2章の8に明記する。
- 評価者としては、(a) の「詳細画面ではナビゲーションのリンクにもクエリを付ける」が、手間が小さく利用者も迷わないので推奨します。(b) を選ぶ場合も、明記されていれば AC7.6 の解釈として受け入れます。

## 推奨（合否には影響しない）

- **連結・単体の混在の注記に確認の手段が無い**: `metric-cagr` の「連結と単体、または会計基準が異なる期を含みます」は実装する項目に挙がっています。しかし、`revenue_cagr_mixed_basis = true` になる投入例も完了条件もありません。9Y004 の5期のうち1期だけ `Consolidated` にする、といった銘柄を1つ足すか、単体テストで確かめる旨を書くと、Sprint 9（F15）で文言を差し替えるときの足場にもなります。
- **「訂正あり（2件）」の件数の意味**: `disclosure_count` は元の開示を含めた件数（9Y001 の FY0 は元の開示と訂正で2件）です。「訂正あり（2件）」は「訂正が2回あった」とも読めます。「開示2件（訂正あり）」のような表記にするか、`title` で「元の開示と訂正の2件」と補ってください。
- **C1-2 の行全体のクリック**: 行のほかの部分をクリックしたときの遷移を JavaScript で作る場合は、次の点も E2E で確かめてください: 行の中のリンクをクリックしたときに二重に遷移しない、中クリック（`auxclick`）でも新しいタブに開ける。
- C4-9 の抜き取り比較には、`market` と `sector` を同時に指定した組（例: `market=0113&sector=5250`）も1つ入れておくと、`matchesFilters` の組み合わせの取りこぼしに気づきやすくなります（C10-1 で網羅されるなら不要です）。

## R1〜R3 の確認

- **R1（解消）**: C4-6 の不正な値が `years=0` になり、書式違反の例として `years=4.95` が加わりました。範囲の上限が 1〜100 のままであることの確認として、有効な例 `years=99`（注記は出ず、99991 の条件③は met。4.0 ≤ 99）も加わりました。C8-4 の `?cagr=abc&years=0` → 400 `fields: ["cagr","years"]` と、画面は既定値で置き換えて 200 を返すことの対比も明記されています。
- **R2（解消）**: 第2章の3に規則が入りました。月末なら前年の同じ月の末日、月末以外なら前年の同じ月の同じ日、そして終了日がちょうど一致する期を探す、の3点です。C10-3 の期待値を手計算で確かめました。
  - 2月決算: FY0 = 2026-02-28。FY-1 は「開始日の前日」の 2025-02-28 で、期が無いので missing。月末なので FY-2 の想定は 2024-02-29 で、期があるので `missing: false`（2023-03-01〜2024-02-29 は 366 日で、変則決算ではない）。FY-3 は FY-2 の期の開始日の前日の 2023-02-28 で missing。月末なので FY-4 の想定は 2022-02-28 で missing。いずれも正しい。
  - 20日締め: FY-1 = 2024-08-20 で missing、FY-2 = 2023-08-20 で `missing: false`。正しい。
  - 3月決算の欠け（9Y002 と同じ形）: FY-3 = 2022-03-31 で missing、FY-4 = 2021-03-31 で `missing: false`。正しい。
  - 補足: 2024-02-28 はうるう年なので月末ではなく、前年の同じ日の 2023-02-28 になります。規則の上でも矛盾は無く、日付のずれも起きません。
- **R3（解消）**: 案 (a) が採られました。詳細画面と「見つからない」画面の間だけ、ナビゲーション（デスクトップとドロワー）の「スクリーニング」の `href` を、パンくずと同じ正規形のクエリにします。C7-5 で、ほかの画面では `/screening` のままであること、クエリが無い場合、未知のパラメータや不正な項目を除くことまで判定できます。E2E の対象にも入っています。

## 9Y004 の FY-4 を連結にした変更の影響（確認済み）

- `financial_metrics_from_periods` は、`v_cons[1:5]` の値の種類が2つ以上なら `revenue_cagr_mixed_basis = true` にします。CAGR の算出（(285.61/100)^(1/4)−1 = 30.0%）と、営業利益率（FY0 だけ。-5.0%）は変わりません。連結・単体の違いは、算出不可の理由にもなりません。
- `financial_periods` の期の選択は、`(code, fiscal_year_end)` ごとに出典の中で行います。同じ期に連結と単体の2件がある形ではないので、選ばれる行は変わりません。5期の表の金額（10,000／500 …）もそのままです。
- 条件の状態（met・unmet・met）、結果に含まれない理由（条件②を満たさない）、「算出に使用」の印、C4-9 の組の期待値も変わりません。C4-9 の2つの組も確かめました。`/stocks/9Y004?market=0113&sector=5250&off=margin` は、グロース・情報通信で、条件②がオフ、①③が met なので含まれます。`/stocks/99991?market=0113&sector=3050` は、業種 5250 のため絞り込みの対象外です。
- `revenue_cagr_mixed_basis = true` になるのは 9Y004 だけです。99990〜99999 と 9Y001〜9Y003 はすべて `Consolidated_JP` です。
