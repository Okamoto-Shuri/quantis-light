## 重点の確認

1. **C3-5 を実際の失敗の経路で（本番相当・dev）**
   - 本番相当での評価者の手順と結果:
     1. `alter table … add constraint eval_fail_snapshot check (false) not valid` を付けてから、`/api/cron/daily` を呼んだ。
     2. 応答は 200（2つの実行を作る）。
     3. 銘柄マスタの実行の `details` は `{"snapshot":"failed"}`。記録は 39・40 のまま増えなかった。
     4. `/imports/runs/5595` に「比較の基準（前回の取り込み時点）を記録できませんでした。前回の記録で比較します」が出た。
     5. 記録に成功した実行（5591）には、この文言が出なかった。
     6. 制約を外した。
   - dev では、E2E の C3-5 が成功した。
   - R5（キーありの経路）は、巻き戻すトランザクションで確かめた。
     - `start_ingestion_run('stock_master','cron')` → `complete_stock_master_run(…, '{"fixture":"x","snapshot":"forged"}')` の後の `details` は、`{"fixture":"x", …, "snapshot":"captured", "snapshotId":42}`（開始時の値が勝つ）。
     - 財務の実行を `finish_ingestion_run`（`{"a":1}`）で終えると `{"a":1}` で、`snapshot` のキーは現れない。
2. **R3: 除外の件数が変更前と一致**
   - 変更前の式（`ok_a`・`ok_b`）を SQL で書き直し、`screen_stocks` の3つの値と比べた。
     - 比べた値: `total`・`excludedUnavailable`・`excludedUndeterminable`

     - データは、第5章の変化を入れた DB と、財務・初出日を消して算出不可を作った DB（巻き戻し）の2つ。
   - 結果は **192/192 で一致** した。算出不可で除外される例は延べ 160 件、判定不能で除外される例は延べ 40 件あった。
   - 既存の `screening.spec.ts`・`ownership.spec.ts` の件数の期待値も、変えずに通っている。

## 軽微な指摘（合否に影響しない）

### m1: メモに NUL 文字（U+0000）を含む PATCH は 500 になる（400 にすべき）
- 重要度: Minor
- 再現手順: `PATCH /api/watchlist/9U003`、本文 `{"memo":"a\u0000b"}`（同一オリジン）
- 期待結果: 400 `invalid_memo`
- 実際の結果: 500 `{"error":"internal_error"}`。Postgres の text は NUL を保存できず、DB の例外がそのまま内部エラーになる。
- 画面の入力欄からはふつう入らない。一方、API の入力の検証の穴であり、ログにエラーが残る。

### m2: 保存に失敗した直後（フォーカスが「保存」ボタン）に Esc を押しても編集を取り消せない
- 重要度: Minor
- 再現手順:
  1. ウォッチリストで 9U001 の「編集」を押す。
  2. 1,001 文字を入れて「保存」を押す（エラーの文言が出て、フォーカスは「保存」に残る）。
  3. Esc を押す。
- 期待結果: 取り消して、元のメモに戻る（契約「Esc で取り消し」）。
- 実際の結果: 何も起きない。Esc の処理が textarea の `onKeyDown` にしか無い。
- 「キャンセル」ボタンでは取り消せる。

### m3: 取り込み状況の「うち、データ期間開始以前から上場」の数に、上場廃止の銘柄が含まれる
- 自己評価の既知の問題どおり。同じ区画のほかの数は上場中だけなので、数の間の整合が崩れる。

### m4: 銘柄詳細の星の、見える文字とアクセシブルな名前の不一致（WCAG 2.5.3）
- 案: `aria-label` を「ウォッチリスト登録済み（外す）: 9U011 …」のように、見える文字で始める。
